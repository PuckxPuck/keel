## Fix pass (2026-10-23)

- Leak replay: fixed. The app records the delivery id with `Verifier.Seen` in the revoke transaction and passes `replayed` to `ReportLeaks`, which then only answers. The revoke is conditional, so only the report that wins it audits `apikey.leaked` and runs `OnLeak`; a report of a key already revoked is audited once as `apikey.leak_reported` with no hook. Concurrent test (two reports racing, then a replay) alerts once; it alerted twice with the old loser path.
- Future `deprecatedOn`: fixed. `apikeys.Check(api, now)` refuses a deprecation date still to come, so `Sunset` is added in the release that deprecates; `Build` now takes a context for that check.
- OpenAPI security: fixed. `apikeys.Document` declares an HTTP bearer scheme (`apiKey`) on the api realm and `Expose` attaches it to every mirrored operation whose `Need` is not public. Asserted in the api realm test.
- P4 handoff: written into tenancy.md and integrations.md (two-step key resolution through `apikeys.Locator` and a global `api_key_tenants`, operator-pool leak and reminder jobs, `OneTenant` keyed by tenant). Identities and passkeys stay global with a realm column rather than gaining `tenant_id`.
