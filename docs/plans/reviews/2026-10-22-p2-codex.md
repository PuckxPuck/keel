## Findings

### Blocker

- **[internal/kit/paging/page.go:183](internal/kit/paging/page.go:183), [internal/kit/paging/keyset.go:150](internal/kit/paging/keyset.go:150)** — Cursor values lose their SQL types. UUIDs, integers, unsigned integers, and booleans are serialized with the `s:` prefix and restored as Go strings. PostgreSQL infers the parameter type from the compared column, then pgx’s binary codecs cannot encode a string as `uuid`, `int4`, etc. Consequently, second-page PostgreSQL queries will fail for every tested sort because the final ID is also restored as a string.  
  Suggested fix: make sort keys carry a typed cursor codec/extractor and restore native `uuid.UUID`, integer, boolean, date, and timestamp values before binding. Add live PostgreSQL/MySQL second-page tests for every supported type.

- **[internal/kit/migrate/validate.go:149](internal/kit/migrate/validate.go:149)** — The migration parser only flushes when a line ends in `;`; it does not split multiple statements on one line. For example, `create table safe (...); drop table users;` is counted as one MySQL statement, while contract detection only examines the initial `create table` prefix. This bypasses both the one-statement MySQL rule and destructive-change detection.  
  Suggested fix: use a SQL-aware lexer that handles top-level semicolons, quotes, comments, and PostgreSQL dollar quoting. Add same-line multi-statement and hidden destructive-DDL regression tests.

- **[deploy/db/postgres-roles.sql:18](deploy/db/postgres-roles.sql:18), [internal/kit/testdb/postgres.go:154](internal/kit/testdb/postgres.go:154)** — Role security attributes are only set when roles are first created. A pre-existing `keel_app` that is superuser or has `BYPASSRLS` remains unsafe, defeating the tenancy boundary; testdb likewise silently accepts existing roles.  
  Suggested fix: follow creation with unconditional `ALTER ROLE` statements enforcing `NOSUPERUSER`, `NOCREATEDB`, `NOCREATEROLE`, `NOREPLICATION`, and the intended `BYPASSRLS` state. Validate both `rolsuper` and `rolbypassrls` in tests.

### Should-fix

- **[internal/kit/db/tx.go:185](internal/kit/db/tx.go:185)** — After-commit callbacks receive the original request context. If it is canceled immediately after a successful commit, the persisted change remains but hooks can silently skip their side effects. The callback signature cannot report failures either.  
  Suggested fix: run hooks with `context.WithoutCancel(ctx)` plus an explicit bounded timeout/failure handler, and test cancellation immediately after commit.

- **[internal/kit/migrate/migrate.go:263](internal/kit/migrate/migrate.go:263), [deploy/db/postgres-roles.sql:31](deploy/db/postgres-roles.sql:31)** — The `SECURITY DEFINER` function correctly fixes its `search_path` and fully qualifies the protected table, but it inherits PostgreSQL’s default `EXECUTE` privilege for `PUBLIC`. Any additional role granted database access can invoke it as the owner.  
  Suggested fix: revoke default function execution from `PUBLIC`, explicitly grant it to the app/operator roles, mirror those privileges in testdb, and test the ACL and function owner.

- **[db/migrations/mysql/20261022150838_kit_locks.sql:3](db/migrations/mysql/20261022150838_kit_locks.sql:3)** — Lock names inherit the database’s collation, normally case- and accent-insensitive. Names such as `foo` and `FOO` collide; the second caller then either waits on an unrelated lock or fails the exact-name check. PostgreSQL behaves differently.  
  Suggested fix: give `locks.name` an explicit binary collation and add case/accent distinction tests on both engines.

- **[internal/kit/migrate/locker.go:21](internal/kit/migrate/locker.go:21)** — `goose:` plus `DATABASE()` can exceed MySQL’s 64-character named-lock limit for a valid 64-character database name, preventing migrations.  
  Suggested fix: derive a fixed-length lock name with SHA-256, using the same expression for acquisition and release.

- **[internal/kit/db/db.go:288](internal/kit/db/db.go:288)** — `openMySQL` dereferences `u.User` without checking it. A syntactically valid URL such as `mysql://db.internal/app?tls=true` passes configuration validation and then panics during startup.  
  Suggested fix: validate a non-nil/nonempty user, host, and database before accessing them and return a credential-free configuration error.

- **[internal/kit/paging/page.go:85](internal/kit/paging/page.go:85)** — `o.Page * o.Limit` can overflow before the depth check. Large request integers can bypass the guard and produce a negative or wrapped offset.  
  Suggested fix: compare using division, such as `Page > maxDepth/Limit`, before multiplication, then calculate with checked `int64` arithmetic.

- **[internal/kit/testdb/mysql.go:120](internal/kit/testdb/mysql.go:120)** — Once `clone` creates the target database, any later failure leaves that database behind until the janitor considers it stale. Repeated failures can accumulate databases on the shared test server.  
  Suggested fix: install a cleanup defer immediately after creation and disable it only after cloning succeeds.

## Fix pass

- Typed cursors (blocker): fixed. `paging.Sorts[R]` keys read values through typed accessors; the cursor stores a type tag and binds uuid, int64, bool (0/1 on MySQL), string, time and decimal as Go values. Live walk tests on both engines cover uuid, typed id, int, bool, nullable date, time and a joined row.
- Migration parser (blocker): fixed. Statements are split as goose splits them, then on top-level semicolons outside literals, comments, quoted names and dollar quotes; the MySQL rule counts real statements and contract detection sees every one. Same-line and comment-hidden cases are table rows.
- Role attributes (blocker): fixed. `deploy/db/postgres-roles.sql` and testdb reset superuser, createdb, createrole, replication and bypassrls on every run (only for roles that drifted, so a clean rerun needs no superuser), and testdb refuses to run when the connected app role is a superuser or bypasses RLS.
- After-commit context: fixed. Hooks run on `context.WithoutCancel(ctx)` with a 30-second timeout; tested by cancelling from an earlier hook.
- Function ACL: fixed. Created by a kit migration with EXECUTE revoked from PUBLIC and granted to the app and operator roles; ACL and owner tested.
- Lock collation: fixed (`utf8mb4_bin`, migration edited in place); case and accent test on both engines.
- MySQL lock name length: fixed (hashed past 64 characters, same name for lock and release).
- `openMySQL` without a user: fixed (returns an error, tested).
- Offset overflow: fixed (`Page > maxDepth/Limit`, tested).
- Failed MySQL clone: fixed (dropped on failure).
- Zero uuid in 16-byte scan: fixed, and `Value` of the zero id is now an error.
- Retry classification: changed against this review's note. MySQL 1205 is no longer retried, matching Postgres 55P03 (InnoDB rolls back only the statement).
