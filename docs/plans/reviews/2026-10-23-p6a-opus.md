Scope:
- internal/app: build.go, wiring.go, services.go, serve.go, files.go, maintenance.go, tenancy.go and tenancy_off.go, doctor.go, commands.go, config.go, deploytest.go, and their tests.
- Kit changes from this phase:
  - jobs: schedule build stamps, unknown kinds.
  - webhooks: secret overlap, replay tenant.
  - rbac: Extend and Holders.
  - migrate: the NO TRANSACTION rule.
  - db: ValidateMigrate and VerifiesTLS.
  - httpx: the Serve option.
- The two new migrations, cmd/keel/gen.go (ErrorModel check), deploy/test/switch_test.go, deploy/systemd/app.env and deploy/k8s/configmap.yaml.

I did not review internal/modules/notes (in progress elsewhere).

## Verdict: fix-then-ship

The wiring does what the brief asks:
- Production startup gets the mail notifier. The production-profile deploy case passes.
- Maintenance runs on maintenanceTx. That is the operator pool under tenancy, and nothing reaches it from a request path.
- File routes run inside the realm chain, with the tenant guard and default-deny readers.
- Replay and leak notices carry the right tenant.
- migrate reads only database settings, and serve still refuses unsafe setups.
- The notenancy build is equivalent.

There is one blocker. One P6a test hard-codes an empty module list, so the gate went red the moment the notes module was mounted. The rest of this review covers:
- doctor accuracy and bounds;
- two latent permission and tenancy gaps that a module will hit next;
- the schedule stamp, which is missing in the documented Docker build.

## Blockers

1. **TestBuild_JobsMountOnTheModuleInstancesItServes fails as soon as any module is mounted.**
   - **Where.** internal/app/services_test.go:146 asserts `built.Modules == []Module{probe}`.
   - **Now.** The notes module is in `modules()`, so `go test -race ./internal/app` fails here (verified, Postgres + MySQL).
   - **Same problem elsewhere.** internal/app/access_test.go:151 uses `notes.read` as its "unknown permission", and that code is now real.
   - **Why it matters.** keel is a template, so every app's first `make:module` reddens `keel check`.
   - **Fix.**
     - Assert that `built.Modules` ends with the probe instance, and that `made` has length 1 (one instance per wiring).
     - Use a code no module can own, such as `zz_unknown.read`.
   - **Proof the rest is clean.** In a copy with `modules()` reverted to empty, internal/app passes with -race on both engines and with `-tags notenancy`.

## Should-fix

2. **doctor's database checks are unbounded. Against an unreachable host it ran for 76s.**
   - **Where.** doctor.go:72 calls `OpenDatabase(ctx, cfg)`, and checkDatabase/checkClock run on the CLI context with no timeout. db.Open pings without a connect timeout.
   - **Spec.** cli.md says network checks give up after three seconds.
   - **Probe.** `APP_DATABASE_URL=postgres://...@10.255.255.1:5432/...` took 76s; it was still running at 8s.
   - **Fix.** Wrap OpenDatabase and each DB check in `context.WithTimeout(ctx, probeTimeout)`.
   - **Also.** checkFiles uses `2*probeTimeout` (doctor.go:280). Either use 3s or document 6s.

3. **doctor drops or mislabels checks when OpenDatabase fails.**
   - **Where.** doctor.go:72-83.
   - **Mislabelled.** Any OpenDatabase error is shown as `database`, including:
     - a roles refusal from CheckTenancy, which should be `roles`;
     - a tenancy schema mismatch.
   - **Missing.** When migrations are behind, the reachability, roles, RLS, jobs and clock lines disappear entirely. Locally that left 8 lines, with no `database` line at all.
   - **Fix.** Open the pools without the CheckCurrent and startTenancy gates for doctor (`db.Open` plus `tenancyPart`). Then run every check, letting checkMigrations and checkTenancy report their own failures.

4. **doctor's mail check can pass a server that cannot send.** This is a false pass.
   - **Where.** doctor.go:266-271.
   - **What it checks.** Only that STARTTLS is *offered*. It never runs the handshake (so certificate or hostname errors pass) and never authenticates (so a wrong password passes).
   - **Failure.** Doctor is green while every mail.send fails.
   - **Fix.**
     - Call `c.StartTLS(&tls.Config{ServerName: host, MinVersion: tls.VersionTLS12})`.
     - When `SMTP.User` is set, call `c.Auth(...)`.
     - Neither sends a message.

5. **The schedule build stamp is empty in the documented Docker build, so the flip-flop guard does nothing there.**
   - **Why it is empty.** Dockerfile:11 defaults `BUILD_TIME=""`. operations.md:20's build command passes no BUILD_TIME. `.dockerignore` drops `.git`, so the vcs.time fallback is empty too.
   - **Effect.** At schedule.go:56 two unstamped builds compare equal, so each process start rewrites the spec. That is the flip-flop the brief asked to remove, still present on k8s rolling updates.
   - **Fix.**
     - Pass `--build-arg BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ)` in operations.md.
     - Either fail the image build on an empty value, or have jobs.New log a warning when `Options.Build` is empty.
   - **Also.** Validate that the stamp is at most 64 characters in jobs.New. Today a longer one makes the first sync fail on the column check.
   - **Rollback.** Document in operations.md (rollback paragraph) that a rollback keeps the newer build's schedule specs.

6. **Modules are built before files are opened.**
   - **Where.** wiring.go:140 calls `mounted(w)`, then build.go:189 calls `openFiles`.
   - **Failure.** A module that takes `w.files` or `w.signer` in its Deps (notes attachments will) gets nil and 503s or panics.
   - **Fix.** Open files inside newWiring before `mounted(w)`, then register maintenance after.

7. **Uploads need only a sign-in.**
   - **Where.** files.go:79 uses `rbac.SignedIn()` for every kind.
   - **Failure.** Once an app adds a kind, any member, device session or read-mostly role can stage files up to the kind's cap. Storage abuse is bounded only by rate limits.
   - **Fix.** Give each kind a `Need`, for example `filePolicies map[string]struct{ Policy files.Policy; Need rbac.Code }`, and check it in `uploadFiles` before streaming.

8. **A suspended tenant's public links keep serving.**
   - **Where.** fileshttp.go:73-83 switches the context to the tenant in the signature after the guard has run. On the shared host there is no host tenant, so tenancy.Guard (http.go:160) passes through. On another tenant's host, the guard checked the wrong tenant.
   - **Failure.** A suspended tenant's public files stay downloadable until each link expires, against "every request refused".
   - **Fix.** In `publicFiles`, refuse when the host tenant is set and differs from the signed one, and load the signed tenant's state (refuse unless active or read-only).

9. **No app-level test covers the file routes.** These are new security behaviour: default-deny readers, cross-tenant 404, guard and read-only refusal, and the public link's tenant binding.
   - **Fix.** Add one table test in internal/app with a local driver and one test kind, mounted through extraModules or a test hook:
     - uploader reads;
     - other member 404;
     - other tenant 404;
     - read-only tenant upload refused;
     - public link wrong host refused.

10. **Setup's Extend restores permissions an administrator removed from a built-in role.**
    - **Where.** rbac/access.go:127-176 compares against the role's current permissions. SetRolePermissions (access.go:262) allows editing built-in roles.
    - **Status.** packages.md documents this. It is latent, because no operation edits roles yet.
    - **Failure.** An app adds a roles API. A tenant admin narrows Administrator. The next deploy's `app setup` silently re-grants the permission, and only the audit log shows it.
    - **Fix.** Pick one:
      - make SetRolePermissions refuse removing permissions from a built-in role (422 `builtin_role`), so the documented rule is enforced; or
      - record the codes setup has offered per role and add only codes never offered.

11. **Stray binaries would be committed.**
    - `/app` (50 MB, built 02:25) is not gitignored.
    - `cmd/keel/keel` (22 MB) is not ignored either, because `.gitignore` anchors `/keel` to the root.
    - **Fix.** Delete both, and add `/app` and `/cmd/*/keel`, or simply `/app` plus `keel` unanchored.

## Nits

- **k8s configmap.yaml:13.** The comment says the write timeout is 60s, but nothing sets `APP_HTTP_WRITE_TIMEOUT`, so k8s gets 30s while systemd gets 60s. Set it, or fix the comment.
- **maintenance.go:83.** Without a lane named `slow`, the hour-long files sweep and the tombstone prune take a fast-lane worker. Prefer the last lane, or document it.
- **config.go:241.** The pool budget is checked only for in-serve workers. `app worker` with `MaxOpen` below its worker count queues on the pool. Check it in the worker command too.
- **Upload read timeout.** fileshttp.Upload does not extend the read deadline, so large uploads over slow links die at `APP_HTTP_READ_TIMEOUT` (30s). Extend it the way downloads extend the write deadline.
- **webhooks.go:585-600.**
  - Rekey reseals previous secrets that have already expired.
  - Expired previous secrets are never cleared.
  - Fix: null `previous_secret` when `previous_secret_until <= now`, in rekey and on the next rotate.
- **doctor.go:341-350.** `weak` is built by ranging over a map, so the order of names varies between runs.
- **doctor.go:366.** The build line reads "dev , build time unknown" when the commit is empty.
- **doctor.go:295 and 305.** The probe is deleted twice. The local driver may also leave an empty `doctor/` directory: the test only checks entries, not the directory.
- **access_commands.go:98.** It says "in one transaction", but under tenancy setup runs one operator transaction plus one per tenant (rerun-safe, not atomic).
- **build.go:72-85.** `installProblems` is a `sync.Once`, so the module mappers installed are those of the first call. That is harmless in production, but a test that mounts extra modules after an earlier Build gets no mapper.
