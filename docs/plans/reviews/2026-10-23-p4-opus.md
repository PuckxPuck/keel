# P4 review (Opus): tenancy

Scope: the 22 `*_tenancy_*.sql` migrations, internal/kit/tenancy, the tenancy edits in internal/kit/{db,migrate,testdb,audit,rbac,idempotency,ratelimit,jobs,mail,webhooks,oauthstate,files,fileshttp,paging,apikeys,auth}, internal/app/{tenancy,tenancy_test}.go and the tenancy edits across internal/app, cmd/keel/{tenantlint,tenantlint_test,steps}.go and .golangci.yml. deploy/ was not reviewed.

## Verdict: fix-then-ship

The boundary works where row-level security is in place. All 16 tenant tables enable and force RLS. Their policies refuse a foreign or null tenant on write. Composite foreign keys stop cross-tenant references. The transaction-local `set_config` cannot leak between pooled transactions, and the D30 re-read rolls back a tenant transaction whose setting moved. I confirmed each of these with probes, not by reading alone.

The weak spots are around that boundary:
- A table that has no `tenant_id` at all is invisible to every check.
- The global tables that decide entry (`memberships`, `tenants`) can be written for any tenant.
- The D30 lint and the forbidigo rule can each be bypassed in one line.

## Blockers

1. **internal/kit/tenancy/catalogue.go:106-111: a tenant table without `tenant_id` passes every check. This is a plan gap.**
   - **What is wrong.** `CheckCatalogue` only looks at tables that have a `tenant_id` column. The migrate lint (`internal/kit/migrate/validate.go:419-450`) only fires when a file adds that column. `TestUnsetTenant_SeesNoTenantRows` (tenancy_test.go:127-129) only walks tables that already have RLS.
   - **Probe.** `create table probe_lines (id uuid primary key, role_id uuid not null references roles (id), body text)` makes `CheckCatalogue` return nil. Every tenant's app role then reads and writes every row.
   - **Why it blocks.** Forgetting the column is the most likely mistake an app developer makes. It is also the one that fails open, which D16 and AGENTS rule 11 exist to prevent. The spec scoped the check to "every table with a tenant_id column", so this is a gap in the plan, not a defect in the coder's work.
   - **Fix.** Make `CheckCatalogue` fail on any table in `public` that has neither a `tenant_id` column nor an entry in an explicit global allowlist. Use `KitExceptions` for kit tables, a new list of global kit tables (`users`, `credentials`, `sessions`, `locks`, ...) and app-supplied exceptions, each with a reason. Also fail on any foreign key from a table without `tenant_id` to a tenant table. In `migrate.Validate`, require `-- keel:global` on any Postgres `create table` without `tenant_id` once the tenancy part is present.

## Should-fix

2. **catalogue.go:136-152: the policy check matches on a substring and ignores extra permissive policies.**
   - **What is wrong.** A table passes as soon as one `ALL` policy mentions `current_setting('app.tenant_id'` in both `using` and `with check`.
   - **Probe.** Both tables below passed:
     - `probe_loose` has the correct policy plus `create policy oops on probe_loose for select using (true)`. Permissive policies OR together, so every tenant reads every row.
     - `probe_fake` has a policy `using (current_setting('app.tenant_id', true) is not null or true)`.
   - **Fix.** Fail on any permissive policy other than the one tenant policy, apart from named exceptions (the three `global_read` policies). Require the `using` and `with check` expressions to compare `tenant_id` with the setting, by normalising `pg_policies.qual` against the canonical expression. Also flag `security definer` functions in `pg_proc` (tenancy.md section 4 forbids them).

3. **Global tables that gate entry can be written for any tenant from a tenant transaction.**
   - **What is wrong.**
     - `20261022192143_tenancy_memberships.sql:68-77` has no RLS and no column default.
     - `20261022192140_tenancy_tenants.sql:15-31` revokes only insert, delete and truncate.
   - **Probe.** From a `Tx[Tenant]` of acme I ran `UPDATE tenants SET slug='globex-renamed', name='pwned' WHERE id=<globex>` (1 row) and `INSERT INTO memberships (<globex>, ann, ...)` (1 row). `Service.Enter(globex, ann)` then succeeded.
   - **Impact.** No HTTP path writes either table today. But the first "invite a member" feature in an app will, and it will have to write the tenant id by hand, against hard rule 3. `Service.SetState` (service.go:139-167) also takes any tenant id inside a tenant transaction.
   - **Fix.**
     - `memberships`: enable and force RLS, with a policy `for select using (true)` (sign-in still reads across tenants) and an insert, update and delete policy with `tenant_id = setting`. Give `tenant_id` the usual column default.
     - `tenants`: revoke update from the app role, grant update on `(status, status_reason, updated_at, version)` only, and add an update policy `using (id = setting)`.
     - `SetState`: refuse an `id` other than `db.TenantOf(ctx)` in a `Tx[Tenant]`.

4. **.golangci.yml:44-46: modules can switch tenant without touching `db.WithTenant`.**
   - **What is wrong.** `tenancy.WithTenant(ctx, tenancy.Tenant{ID: x})` (tenancy.go:98-102) and `apikeys.TenantTx(d)(ctx, apikeys.Tenant{ID: x}, fn)` (apikeys/public.go:192-197) are exported. Each opens another tenant's transaction, and lint allows both. D35 says "lint keeps modules from setting it", which is not true today.
   - **Plausible failure.** An inbound webhook handler in a module does `tenancy.WithTenant(ctx, tenancy.Tenant{ID: payload.TenantID})`.
   - **Fix.** Add forbidigo rules for `^tenancy\.WithTenant$` and `^apikeys\.TenantTx$`, with the same `internal/(kit|app)|cmd|_test` exclusion.

5. **The D30 controls have two holes.**
   - **Plain transactions are not checked.**
     - **What is wrong.** `Install` (tenancy.go:150-186) registers hooks for `db.Tenant` only, so a `Tx[Plain]` under tenancy has no begin or commit guard.
     - **Probe.** A plain transaction that runs `set_config('app.tenant_id', <globex>, true)` read globex's rows and committed with no error.
   - **The lint regex is easy to evade.**
     - **What is wrong.** The regexes are at cmd/keel/tenantlint.go:18-20.
     - **Probe.** `SET "app"."tenant_id" = '<globex>'` ran fine and was not flagged. Neither were `ALTER ROLE ... SET "app"."tenant_id"` or `SET app . tenant_id`. The quoted form is session-level, so it outlived the transaction. With `MaxOpenConns(1)`, the next plain transaction on that pooled connection saw globex's rows (`rows=1`).
   - **Fix.**
     - Under tenancy, register `OnBegin[Plain]` to run `select set_config('app.tenant_id', '', true)`, and `BeforeCommit[Plain]` to check that it is still empty. Plain transactions then cannot inherit or carry a tenant, even from a session-level leak.
     - In the lint, strip double quotes and collapse whitespace around `.` before matching, and flag any line that names `app` and `tenant_id` together.

6. **A removed member's session locks them out on the shared host.**
   - **What is wrong.** `RemoveMember` (tenancy/store.go:180-185) bumps the user's access version but leaves their sessions with `current_tenant_id` set. `sessions.Resolve` puts that tenant in the context (auth/resolve.go:141-151). Then `Guard` (tenancy/http.go:150-181) refuses everything the user sends.
   - **Probe.** Carol was a member of acme and globex, signed in on the shared host, then was removed from acme. Following the rotated cookie, all of these returned 403 `not_a_member`: `GET /me`, `POST /auth/sign-out`, `POST /auth/tenant` and `POST /auth/sign-in`. Only a request with no cookie worked. A bearer client is stuck until the session's idle expiry.
   - **Fix.** Make `RemoveMember` delete or retarget the user's sessions whose `current_tenant_id` is that tenant, as `SetState` does on suspension. Separately, when the tenant came from the session rather than the host and membership is gone, have `Guard` treat the request as anonymous or clear the session instead of answering 403.

7. **Audit rows land on the wrong trail.**
   - **Shared-host sign-in.** The sign-in transaction is a plain one, so `session.start` is written with `tenant_id NULL` on the global chain. The probe found one acme row for the acme-host sign-in and one NULL row for the shared-host sign-in into acme. Acme's trail therefore never shows its users' shared-host sign-ins.
   - **Leak reports.** Under tenancy, `leakTx` (app/tenancy.go:205-210) opens an operator transaction with no tenant, so `apikey.leaked` and `apikey.leak_reported` (apikeys/leak.go:87-99) also go to the global chain. They never appear on the tenant's trail.
   - **Fix.**
     - Sign-in: record the start in the landed tenant's transaction, for example by opening it after `Admit` picks the tenant.
     - Leaks: load the key's `tenant_id` in the operator transaction and pass it as `Event.Tenant` (with `db.WithTenant` for the `onLeak` enqueue).

8. **db/tx.go:110-113, 240: `Tx.Tenancy()` depends on whether the hooks were registered, not on the schema.**
   - **What is wrong.** `OpenDatabase` (commands.go:201) never calls `tenancy.Install`. Commands that build `Deps{DB: d}` without `Tenancy` therefore run kit stores in no-tenancy mode on a tenancy schema. Today that is `RevokeSessions` (access_commands.go:245) and `Setup`.
   - **Impact.** It is harmless today. But `jobs.insertJob` and `auth.insertSession` change their SQL on this flag, so a future command could enqueue a tenant's job with a NULL tenant.
   - **Fix.** Call `tenancy.Install(d)` in `OpenDatabase` when `deps.Tenancy` is true, or set the flag on `db.DB` from the schema.

9. **catalogue.go:207-260: `CheckRoles` only looks at the attributes of `current_user`.**
   - **What is wrong.** An app role that is a member of the owner or operator role (`GRANT keel_operator TO keel_app`) passes the check. So does an app role that has regained `INSERT` on `tenants` through a later `GRANT ... ON ALL TABLES`. A member can `SET ROLE` to bypass RLS.
   - **Fix.** Also refuse when `pg_has_role(current_user, r.oid, 'MEMBER')` is true for any role that bypasses RLS or owns tables in `public`. Check `has_table_privilege` for insert and delete on `tenants` and any write on `tenant_domains`.

10. **The operator pool is sized but never checked against what uses it.**
    - **What is wrong.** The pool default is 4 (`APP_DATABASE_OPERATOR_MAX_OPEN`, db.go:57). The default worker lanes are `fast:4,slow:1` (jobs/config.go:15). Under tenancy, claims, lease renewals, reaping, scheduling, every global job's handler transaction, operator HTTP traffic and leak reports all draw on those 4 connections.
    - **Failure.** A few global handlers holding operator transactions starve `keepLease`. Leases are then lost and jobs run twice. This is the pool-starvation class every phase has hit.
    - **Fix.** When P5 wires the queue, refuse a configuration where total workers plus a reserve (2) exceeds `OperatorMaxOpen`, or raise the default.

11. **`keel init` cannot remove tenancy by deleting files.**
    - **What is wrong.** internal/app/wiring.go:47 (`tenancy *tenancy.Service`) and commands.go:47-48 (`tenancy.Suspended`, `tenancy.Active`) import kit/tenancy. About 70 lines outside tenancy.go call its helpers (`setupTenancy`, `resolveTenant`, `guardTenant`, `keyLocator`, `leakTx`, `inTenant`, `joinTenant`, `setupOperator`, `grantOperator`, `TenancyConfig`).
    - **Fix.** Keep every kit/tenancy import in internal/app/tenancy.go: move the `tenant:*` command entries there and hold the service behind a small interface. Ship a `tenancy_off.go` stub with the no-op versions for P6 to swap in.

## Nits

12. **No foreign key on null-tenant grants.** In `tenancy_user_roles.sql:151,157` and `tenancy_role_permissions.sql:122-125`, dropping the single-column `role_id` foreign key leaves null-tenant rows with no foreign key, because MATCH SIMPLE skips them. The probe inserted operator grants and permissions pointing at a nonexistent role. Keep `foreign key (role_id) references roles (id)` alongside the composite one.
13. **Prune indexes lead with `tenant_id`, but prunes run across tenants on the operator pool.** The indexes are `idempotency_keys_expires_at`, `jobs_finished`, `mail_outbox_created_at`, `tombstones_deleted_at`, `device_pairing_codes_expires_at` and `api_keys_expires_at`. A skip scan over thousands of tenants is close to a sequential scan. Add catalogue exceptions with the reason "operator prune", or keep a separate time-only index.
14. **Hosts under the tenancy suffix are not checked.** `tenancy.Config.Validate` (tenancy.go:124-129) does not refuse the shared tenant host or `APP_PUBLIC_URL` host under `APP_TENANCY_HOST_SUFFIX`, and no slugs are reserved. A tenant created later with slug `app` would capture `app.<suffix>`.
15. **auth/resolve.go:149-166: a failed principal load keeps the session's tenant.** When the later principal load fails (disabled user), the request continues anonymous with the session's tenant still in its context. A sign-in on the shared host then lands by that tenant, not the default. Drop the tenant from the context on that path.
16. **catalogue.go:197 skips self-referencing foreign keys.** On a nullable-tenant table keyed on `id`, a self-reference without `tenant_id` passes.
17. **jobs/worker.go:177 sets `db.WithTenant` only.** `tenancy.FromContext` returns false inside job handlers. Document it, or note it for P5.
18. **tenancy.go:144 `installed` is a process-global `sync.Map` keyed by `*db.DB`.** It grows in tests and is never pruned.
19. **TestTenancy_IsolationWalk (app/tenancy_test.go:149-153) covers 3 operations.** It does not cover GET of the other tenant's key or device. Files, webhooks and connections have no HTTP surface yet, so P5 must extend the walk.

## P5 handoff (tenancy)

- fileshttp handlers are plain `http.Handler`s outside the huma chain. They must sit behind the tenant resolver and `Guard`, so that membership, suspension and read-only apply, or check them themselves. `Public` already binds the tenant through the signature.
- Wire jobs with `jobs.OperatorTx` and handlers with `tenancy.Runner`, and apply finding 10.
- Mail, webhook delivery and connections must enqueue inside the tenant transaction so that the job carries the tenant.
- Scope the replay and rekey commands to `--tenant`, or run them on the operator pool.

## What I verified and how

- **`go run ./cmd/keel check`:** exit 0. Format, lint, vet, the D30 lint, govulncheck, generated-code drift and tests all passed. Tests came from the build cache.
- **Uncached race run:** `go test -race -count=1 ./...` with `APP_TEST_DATABASE_URL` on 127.0.0.1:5442 and `APP_TEST_MYSQL_URL` on 127.0.0.1:3316. All packages passed in 28 s.
- **Tenancy tests:** a `-v` run of `internal/kit/tenancy` and `internal/app` confirmed the tenancy tests run and are not skipped (7 kit tests and 6 app tests, all passing).
- **Kit probes:** `go test -overlay` with a probe file in internal/kit/tenancy, on Postgres.
  - Each of these writes was refused by the policy: a role inserted with tenant B from tenant A, a null-tenant `user_roles` row from tenant A, and a null-tenant operator role from a plain transaction.
  - Findings 3, 5, 1, 2 and 12 were reproduced as described above.
- **App probes:** `go test -overlay` with a probe file in internal/app.
  - An API key of a suspended tenant gets 403 `tenant_suspended`, as it should.
  - Findings 6 and 7 (sign-in) were reproduced as described above.
- **Confirmed by reading:**
  - `set_config(..., true)` is transaction-local. The begin hook runs before `fn`. The commit hook runs on every successful tenant transaction, read-only ones included.
  - API keys: `Locate` reads only `api_key_tenants`, and `Resolve` runs in the located tenant's transaction.
  - Files: keys carry the tenant segment and `Open` compares it with the context. Signed links MAC the tenant.
  - Feed tokens embed the tenant and are compared on open. `oauthstate.Take` checks the stored tenant.
  - Caching and scoping: the principal cache key includes the tenant, `ratelimit.ByTenant` uses the context's tenant, and the idempotency unique key includes `tenant_id`.
  - Jobs claim `tenant_id` and restore it. Non-global kinds without a tenant fail with `no_tenant`.
  - The operator realm has its own cookie, MFA is required in production, and tenant-realm hosts do not route to its operations.
  - No request path holds a pooled connection while it waits on another: the resolver, session, guard, locator, idempotency and handler transactions all run one after another.

## Fix pass (2026-10-23)

Each probe was run against the code first and showed the leak, then again after the fix.

1. Done. Every table in `public` is a tenant table unless `tenancy.KitExceptions` (or the app's `appGlobalTables`) names it global with a reason. `CheckCatalogue` reports a table without `tenant_id` that is not listed and a foreign key from a global table into a tenant table. `migrate.Validate` follows each table across all files once the tenancy part is present: a table that never gets `tenant_id` needs `-- keel:global <reason>` on its creating file, and the marker needs a reason. `migrate:validate` also checks every marked table is on the allowlist. The kit migrations that create global tables carry the marker now. Probe: `probe_lines` and `invoices` are reported.
2. Done. The tenant policy is compared with the template as `pg_get_expr` prints it (whitespace and column aliases removed): for all commands, permissive, `=` on a not-null `tenant_id`, `=` or `is not distinct from` on a nullable one. Any other policy fails unless excepted by name (`global_read` on the three rbac tables, `locate` on `api_key_tenants`). `security definer` functions fail unless excepted (`keel_migrations_applied`); views must be `security_invoker`. Probe: `probe_loose` and `probe_fake` are reported.
3. Done. The app role has SELECT only on `tenants`, `tenant_domains` and `memberships`. `SetState`, `AddMember` and `RemoveMember` take `db.Tx[db.Operator]`; `user:grant --tenant` adds the membership on the operator pool before the grant. Probe: both writes fail with `permission denied`.
4. Done. forbidigo refuses `tenancy.WithTenant` and `apikeys.TenantTx` outside kit/db, kit/tenancy, kit/apikeys, `internal/app/tenancy.go` and tests; `db.WithTenant` is now limited to kit code, that file, cmd and tests. Checked with a throwaway module file.
5. Done differently from the suggestion, as decided: both pools clear `app.tenant_id` on every connection checkout (`db.ResetTenant`, pgx stdlib's session reset, with the idle ping skipped since the reset is a round trip). Measured: 0.54 ms to 0.72 ms per one-statement transaction on the local Docker Postgres, one round trip. Startup refuses database or role defaults for `app.*`. The lint now reads each line with concatenation, quotes, escapes and spaces around the dot removed and also flags `pg_settings`; a table test holds every form the reviews used. No plain-transaction hooks were added: a set inside a plain transaction lasts only for that transaction and the lint is the control there. Probe: the next borrower reads an empty setting and 0 tenant rows.
6. Done. `RemoveMember` takes the user's sessions out of that tenant. The guard lets a non-member reach `signOut` outside any tenant, and a session whose own tenant the user lost drops it and carries on without a tenant or grants. Probe: `GET /me` 200, sign-out 204, sign-in 200.
7. Done. A shared-host sign-in stays on the global trail and, after commit, `session.entered` goes to the landed tenant's trail. Leak reports record `apikey.leaked` on the key's tenant's trail and run `OnLeak` with that tenant in the context.
8. Done. `OpenDatabase` installs the hooks whenever the build has the tenancy part and refuses a database whose tenancy tables disagree with the build either way.
9. Done. `CheckRoles` walks membership with `pg_has_role`: the app role may not be or reach a superuser, a `bypassrls` role, a role owning tables in `public` or the operator role; it may not write the three control tables; no view in `public` may be owned by a role that bypasses row-level security. Probe: `CheckRoles` now refuses the member of the operator role and the superuser view.
10. Done. Default `APP_DATABASE_OPERATOR_MAX_OPEN` is 8. `APP_JOBS_*` is now part of the app configuration, and under tenancy with an operator URL the configuration refuses an operator pool smaller than the workers plus 2.
11. Done. `internal/app/tenancy.go` (`!notenancy`) holds every kit/tenancy use; `tenancy_off.go` (`notenancy`) has the same names. `keel lint` runs `go vet -tags notenancy ./...`.
12. Documented, not changed: the composite foreign key on a nullable `tenant_id` is MATCH SIMPLE and skips rows without a tenant (docs/tenancy.md section 4). A plain `role_id` foreign key beside it would fail the catalogue check's tenant-pairing rule.
13 to 19. Not in this pass's decisions; left as they were: prune indexes (13), slugs and the shared host under the suffix (14; custom domains are now checked, see the adversarial S7), the tenant kept after a failed principal load (15), self-referencing foreign keys (16), `tenancy.FromContext` in job handlers (17), the `installed` map (18), and the isolation walk (19, P5).
- P5 handoff stands. File handlers are still outside the tenant guard chain; they go to the wiring phase.
