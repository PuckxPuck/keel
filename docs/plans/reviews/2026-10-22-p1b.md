# Review: second half of P1 (2026-10-22)

Scope: internal/kit/httpx (httpx.go, clientaddr.go, cloudflare_ranges.go, middleware.go, recorder.go, returnpath.go, envelope.go), internal/kit/httpx/problem, internal/kit/health, internal/kit/server, tools/cfranges, internal/app (build.go, ping.go, serve.go, the serve command) and their tests. The concurrent fixes to logx, config, ids, dates, money, cli, deploy, CI and the Makefile are out of scope.

Verdict: **fix-then-ship**. There is one blocker: in tunnel mode behind nginx, which is the documented single-host shape, any client that can reach nginx chooses its own IP. The should-fix items are mostly small. Each one either breaks a documented guarantee (body caps, the drain bound, "never touches a live socket") or leaves it untested.

## Findings

1. **blocker**, internal/kit/httpx/clientaddr.go:59-76 and 82-92. The edge check runs on a hop before the trusted-proxy walk.
   - The failure: with `cloudflare-tunnel`, `TUNNEL_ADDR=127.0.0.1` and `TRUSTED=127.0.0.1/32` (cloudflared and nginx share a host, and security.md section 1 requires trusted proxies with an edge mode), nginx's own peer address matches the tunnel. CF-Connecting-IP is then believed for every request nginx forwards, including requests that never passed through the tunnel.
   - Probe: RemoteAddr 127.0.0.1, `X-Forwarded-For: 203.0.113.9` (appended by nginx) and a spoofed `CF-Connecting-IP: 198.51.100.1` resolve to 198.51.100.1. The unix-socket peer (`@`) does the same, because it maps to 127.0.0.1.
   - Impact: the attacker can rotate a fake IP per request, which defeats the per-IP and account-plus-IP sign-in limiter (D31), and the audit IP becomes fiction.
   - Fix: if the hop is trusted and an XFF entry remains, keep walking. Consult the edge header only for the first hop that is not a trusted proxy, or for a trusted hop when XFF is exhausted. Add the case above to TestClientAddress.
2. **should-fix**, clientaddr.go:104-113. A unix-socket peer, and any RemoteAddr that cannot be parsed, becomes 127.0.0.1 and is not marked as proxied.
   - Probe: with nginx on a unix socket and `APP_PROXY_TRUSTED` empty, every internet client resolves to 127.0.0.1 with `proxied=false`. The whole internet shares one rate-limit bucket, and the dev-login gate ("loopback client, no proxy in front") passes for everyone.
   - Socket file permissions do narrow who can connect, but treating a unix peer as "loopback" conflates two different things.
   - Fix: make a unix peer its own kind. Treat it as a trusted proxy hop only when configured (for example a `unix` token in `APP_PROXY_TRUSTED`), and never as a loopback client. An unparseable RemoteAddr should resolve to the zero Addr, not loopback. Config (other owner) should refuse a `unix:` addr in production unless the proxy is trusted.
3. **should-fix**, internal/kit/server/server.go:165-173. removeStaleSocket deletes the socket whenever the dial fails for any reason (EACCES, a timeout on a full backlog), not only when nobody listens.
   - Probe: a live listener whose socket is chmod 000 is unlinked, and a second `Listen` succeeds. This contradicts the comment at :153 and docs/configuration.md ("stale file removed").
   - Fix: remove only when the error is `syscall.ECONNREFUSED`, and refuse otherwise. Add the chmod-000 case to TestListen_UnixSocket.
4. **should-fix**, server.go:94 and 105. A background worker failure calls `stop()`, but because `ctx.Err()` is nil, `graceful` is false and the drain delay is skipped. Probe: readiness flips and Shutdown starts 21 ms after the worker fails, with a 500 ms drain configured. The proxy still routes to the slot and new connections are refused, so a POST (not retried by `proxy_next_upstream`) fails. Fix: drain whenever the server was serving. Skip the delay only when `srv.Serve` itself failed.
5. **should-fix**, server.go:94-97, 108 and 117-126. Shutdown and the worker wait each get a full `ShutdownTimeout`, so the worst case is drain + 2 x timeout. docs/operations.md sizes `terminationGracePeriodSeconds` and the systemd/Docker grace as "drain plus shutdown timeout", which lets the supervisor SIGKILL the process mid-shutdown, after which job leases are abandoned. Fix: compute one deadline when shutdown starts and share it between `Shutdown` and `wait`.
6. **should-fix**, internal/app/build.go:39 with middleware.go:101-112. The body caps do not match configuration.md ("Global cap; operations may set lower or higher").
   - Probe: with `MAX_BODY_BYTES=4MiB`, a 2 MiB body is refused with 413, because Huma's own default per-operation cap is 1 MiB (huma.go `ensureMaxBodyBytes`).
   - Probe: with the global cap at 1 MiB, an operation with `MaxBodyBytes: 8MiB` still gets 413 at 1 MiB from the chi-level cap.
   - Fix: give operations the configured default through the kit registration helper that P3's `Need` wrapper will need anyway. Set the chi-level cap to the largest operation limit, or apply it only to non-Huma routes. Add a test that a configured cap above 1 MiB takes effect.
7. **should-fix**, middleware.go:85-98. Recover writes the problem on top of whatever headers the handler had already set.
   - Probe: a handler sets `Set-Cookie`, `Content-Length: 2` and `Content-Disposition`, then panics. The client gets a 500 that carries the cookie and an empty body (the problem JSON is cut by the stale Content-Length).
   - Fix: snapshot `w.Header()` on entry. On a panic before any write, restore the snapshot (which keeps the request id and the security headers set earlier) and delete Content-Length.
8. **should-fix**, build.go:34-41. SecurityHeaders runs after MaxBody, so the declared-length 413 has no `nosniff` or CSP (probe), and a panic in an earlier middleware gets none either. Fix: put SecurityHeaders right after RequestID, before AccessLog, Recover and MaxBody.
9. **should-fix**, internal/kit/httpx/envelope.go:168-176. When data is an array, the walk test does not require `meta` or `links`. Probe: an operation returning `httpx.One[[]widget]` passes CheckOutputs, which is an unbounded list outside `List` and contradicts api.md ("Every list is paginated"). Fix: for array data, require `meta` and `links` in `schema.Required`, and add the case to TestCheckOutputs.
10. **should-fix**, plan drift against docs/plans/2026-10-22-keel-v1.md:98-103. Three P1 items are missing:
    - the `health` startup gate (readiness should stay off until the app marks startup complete);
    - host routing for realms in `httpx`;
    - the envelope encoder benchmark from "Done when".

    Build them, or move each one explicitly to a later phase in the plan.
11. **should-fix**, internal/kit/health/health.go:54-59. The unauthenticated `/livez` returns `goVersion` and `commit` (probe: `"goVersion":"go1.27.3"`), which tells an attacker exactly which stdlib CVEs apply. Fix: return `{"data":{"status":"ok"}}`. The `about` command already reports the build.
12. **should-fix**, tests missing for real risks. Nothing fails today if `router.Use(crossOrigin)` or `Recover` is dropped from Build, or if the middleware order changes. Add:
    - one Build-level error walk (testing.md "Error walk"): 404, 405, a declared-length 413, invalid JSON and a forced panic, each asserting problem+json, requestId and nosniff. Build needs a way to register a test operation.
    - one Build-level cross-site POST on a Huma route and on a chi route;
    - the tunnel-behind-nginx case (1), the chmod-000 socket (3), and worker failure still draining (4).
13. **should-fix**, internal/kit/server/server_test.go:28-127. The test runs on real sleeps and wall-clock polling, which testing.md forbids ("Never depend on the real date or sleep"). It passed 30 runs here, but on a loaded `-race` runner the flip-detection loop can overrun the 300 ms drain and the `/work` loop will then hit a closed listener. Fix: make the drain wait injectable (for example an `Options` hook that blocks until the test releases it), so the test holds the drain open deterministically and asserts during it.
14. **nit**, internal/kit/httpx/middleware_test.go:188-192. The chunked half asserts a 413 that the test handler writes itself, so it proves nothing. problem_test.go:152 covers the real path. Delete it.
15. **nit**, middleware.go:182-188. `NoStore` is unused, which is dead code. Either wire it in Build (authenticated JSON should not be cached by intermediaries) or delete it.
16. **nit**, internal/kit/httpx/problem/problem.go:85. "Standard members win" is false when the standard member is omitted. Probe: `Extensions{"detail": ...}` on a problem with an empty detail is emitted. Fix: drop any extension key that matches a standard member name.
17. **nit**, problem/install.go:210-222 and 20-37.
    - An unknown_field location echoes the client's property name in full (a 1 MiB key comes back as a 1 MiB location). Cap the location length.
    - Mappers are package-global and `Build` calls `problem.Install()` with none, which silently wipes any mappers installed before it. Pass mappers into Build before modules start registering them.
18. **nit**, internal/kit/httpx/returnpath.go:11-23.
    - It accepts raw non-ASCII and invalid UTF-8 (`"/\xff"`, `"/ x"`), which then lands in a Location header. This is not a host switch, since the WHATWG parser only strips ASCII tab and newline and the second character decides authority. Still, accept printable ASCII only and require percent-encoding for everything else.
    - The `url.Parse` check at :18-21 is unreachable given the prefix checks. Delete it.
19. **nit**, server.go:52-61.
    - Set `DisableGeneralOptionsHandler: true`, so `OPTIONS *` reaches the router instead of getting net/http's empty 200.
    - api.md says nothing writes plain text, but net/http itself answers malformed requests and 431 (headers over MaxHeaderBytes) in plain text before any middleware runs. Say so in api.md.
20. **nit**, server.go:139-150. The socket is created under the process umask and chmodded afterwards. With a loose umask, a local user can connect during that window and keep the connection. Document that the socket's directory carries the access control (systemd `RuntimeDirectory=` with `RuntimeDirectoryMode=0750`), or check the directory mode at start.
21. **nit**, middleware.go:28-39. `X-Request-Id` is accepted from any client, so a client can make many requests share one id and muddy incident correlation. Accept the incoming id only when `Proxied(ctx)` is true (nginx's `$request_id`).
22. **nit**, health.go:48-52. `HEAD /livez` is 405 (probe), and some load balancers probe with HEAD. Register HEAD for both routes.
23. **nit**, comments that restate the code: health.go:48, middleware.go:182, build.go:66. Delete them.
24. **nit**, cloudflare_ranges.go:8. `CloudflareRangesFetched` is exported and nothing reads it. Either have `doctor` warn when the ranges are older than about 90 days, or unexport it.

Out of scope, for the config owner: `Proxy.Validate` requires trusted proxies in production only for `cloudflare`, while security.md section 1 says either edge mode. configuration.md should also say which address `APP_PROXY_TUNNEL_ADDR` is (as seen by the app, which is nginx's address when nginx sits in between). Finding 1 depends on that answer. The second-signal item (p0-p1a #6) is still open in cli.go and was not refiled.

## Fix pass

1. **fixed.** The trusted-proxy walk runs first. The edge rule is applied only to the address where the walk stopped. Regression rows in TestClientAddress cover the review's probe, Cloudflare proxy mode through nginx (believed through a Cloudflare hop, ignored when sent straight to nginx), cloudflared through nginx (the client is the X-Forwarded-For entry Cloudflare wrote), and cloudflared straight to the app.
2. **fixed.** A unix socket peer, detected from the listener's network and not from RemoteAddr, is a trusted proxy only with the `unix` token in `APP_PROXY_TRUSTED` (`config.TrustedProxies`). Otherwise, and for any unparseable RemoteAddr, ClientIP is the zero Addr, which is never loopback. The log shows `client_ip=unknown`. Not done: config refusing a `unix:` addr in production without a trusted proxy. Validation runs per part, so HTTP cannot see Proxy. The config owner needs a cross-part check.
3. **fixed.** A stale socket is removed only on ECONNREFUSED, and nothing is removed when the path has disappeared. Any other dial error refuses to start. TestListen_UnixSocket has the chmod-000 case.
4. **fixed.** The server drains unless `srv.Serve` itself failed. TestServe_FailingWorkerStillDrains covers it.
5. **fixed.** One deadline, drain plus shutdown timeout, is shared by the drain, Shutdown and the worker wait. TestServe_DrainAndShutdownShareOneDeadline covers it.
6. **fixed.** `httpx.Register` gives every operation `APP_HTTP_MAX_BODY_BYTES` (through `Options.MaxBodyBytes`) unless the operation sets its own. MaxBody now wraps only the routes outside Huma (health). Build-level test: a 1.5 MiB body passes with a 2 MiB cap, and an operation set to 4 MiB accepts 3 MiB.
7. **fixed.** Recover snapshots the headers on entry. On a panic it restores the snapshot (request id, security headers, CORS) and drops Content-Length.
8. **fixed.** The order is now ClientAddress, RequestID, SecurityHeaders, AccessLog, CORS, Recover, CSRF. CORS moved ahead of Recover so a 500 keeps its CORS headers.
9. **fixed.** CheckOutputs requires `meta` and `links` when data is an array. A `One[[]T]` case is in the test.
10. **changed.** The startup gate is built: `health.Ready()`, called in serve after listening. Realm host routing moved to P3 in the plan. The envelope benchmark is `BenchmarkListEnvelope`. `keel bench` does not exist yet (cmd/keel is not in this pass's scope).
11. **fixed.** `/livez` returns `{"data":{"status":"ok"}}`.
12. **fixed.** Build-level error walk (404, 405, 413, 400, 422, panic 500), each checked for problem+json, requestId, nosniff and DENY. Build-level cross-site POST on a Huma route and on a chi route. The regression tests listed in 1, 3 and 4. `Build` takes optional extra registrations for test operations.
13. **fixed.** The server tests run in `testing/synctest` on an in-memory pipe listener, with no real sleeps. The worst-case test waits a fake 25 s.
14. **fixed.** The chunked half is deleted.
15. **changed.** NoStore is kept, because docs/packages.md lists it as API for authenticated routes. Only its restating comment was removed.
16. **fixed.** Extension keys that match a standard member are dropped.
17. **fixed.** An unknown_field location is capped at 64 bytes. Install now appends mappers instead of replacing them, so Build's `Install()` no longer wipes earlier ones. Per-API mappers were not cheap, because Huma's error constructors are global.
18. **fixed.** Only printable ASCII is accepted, so anything else must be percent-encoded. A raw space is refused. The unreachable `url.Parse` check is deleted. The fuzz property checks bytes too.
19. **partly fixed.** `DisableGeneralOptionsHandler` is set. Not done: the api.md note about net/http's plain-text 400 and 431, because api.md is outside this pass's files.
20. **fixed.** The socket is bound inside a fresh 0700 directory, chmodded to 0660, then hard-linked into place, so it is never reachable with the umask's mode. A link never clobbers an existing file. The listener removes the final path on close. The umask was not used, because it is process-wide.
21. **fixed.** An incoming X-Request-Id is kept only when `Proxied(ctx)`.
22. **fixed.** HEAD is registered on /livez and /readyz.
23. **fixed.** The three comments are removed.
24. **not done.** cloudflare_ranges.go is generated by tools/cfranges, which is outside this pass's files. `doctor` does not exist yet.

Out of scope, left for the config and docs owners: security.md section 1 says "with a tunnel, cloudflared is the only trusted hop". Since decision 1, cloudflared then nginx on one host with `127.0.0.1/32` trusted is the intended shape, so that sentence should change. docs/packages.md should list `httpx.Register` and `health.Ready`.
