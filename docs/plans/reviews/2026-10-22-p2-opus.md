# P2 review (Opus)

Scope: internal/kit/{db,migrate,testdb,paging}, internal/kit/ids zero-id changes, db/migrations, internal/dbgen (skimmed), cmd/keel/{database,gen,steps}.go, internal/app database wiring, deploy/db.

## Verdict: fix-then-ship

The transaction core is sound. Panic rollback, rollback after a cancelled context, AfterCommit only after a confirmed commit, ErrCommitUncertain classification, per-attempt hook re-runs and the nested-transaction refusal are all correct. The Postgres template-clone testdb is solid. Two things must change before merge: the scope types do not enforce D29, and the MySQL locks table has a collation bug that becomes permanent once the migration is merged. Most should-fix items are cheap and are about what P4 will rely on.

## Blockers

1. **internal/kit/db/tx.go:47-50.** `Tx[Plain]`, `Tx[Tenant]` and `Tx[Operator]` have identical underlying types, so `db.Tx[db.Tenant](plainTx)` and `db.Tx[db.Tenant](operatorTx)` compile from any package. I confirmed this with an overlay test. That defeats D29 in two ways: a Tenant tx can exist without the begin hook, and a tenant store can run on the BYPASSRLS pool. Fix: `type Tx[S Scope] struct { _ [0]S; tx *sql.Tx; dialect Dialect }`, plus a test asserting `reflect.TypeFor[Tx[A]]().ConvertibleTo(reflect.TypeFor[Tx[B]]())` is false for every pair.
2. **db/migrations/mysql/20261022150838_kit_locks.sql:3.** `name varchar(191)` inherits `utf8mb4_0900_ai_ci`, which ignores case and accents. As a result, `Lock("review:case")` after `Lock("review:Case")` fails with `db: lock row mismatch` (lock.go:38), and `cafe`/`café` also collide. I verified both. Postgres treats these names as distinct, so the two engines diverge. Once merged, the file is append-only. Fix: `name varchar(191) character set utf8mb4 collate utf8mb4_bin not null primary key`, and add case and accent variants to the lock contract test.

## Should-fix

3. **internal/kit/db/errors.go:51-53 and errors_internal_test.go:35.** MySQL 1205 (lock wait timeout) is retried, but the plan and packages.md say only serialization failures and deadlocks are retried. The Postgres counterpart, 55P03, is not retried, so the engines diverge. With the 10s innodb timeout and 2 retries, one contended request can block for 30s or more. InnoDB rolls back only the statement on 1205, so the `IsRetryable` doc is wrong for callers outside InTx. Fix: drop 1205 and flip the test row.
4. **tx.go:102-109, 66-80; db.go:191-192.** The operator capability only exists by convention. Any holder of `*db.DB`, which every module gets through `app.Deps`, can call `db.GrantOperatorAccess(d)`. It can also register a no-op `OnBegin[Tenant]`, which satisfies the check at tx.go:138-142, or reach the raw pool through `SQL()`. The plan's risk table promises a lint for this, and none exists in .golangci.yml. Fix: have `Open` return `(*DB, *OperatorAccess, error)` and delete `GrantOperatorAccess`. Alternatively, add forbidigo rules with `analyze-types` for `GrantOperatorAccess`, `OnBegin`, `BeforeCommit` and `(*DB).SQL` outside internal/app, internal/kit and tests.
5. **tx.go:53.** `Q()` returns the `*sql.Tx` itself, so `tx.Q().(*sql.Tx).Commit()` works. That commit skips BeforeCommit (the D30 re-read) and AfterCommit, and InTx then reports a commit error for a transaction that did commit. Fix: return an unexported wrapper that exposes only `QueryContext` and `ExecContext`.
6. **internal/kit/migrate/migrate.go:80-84, 263-265.** I checked `public.keel_migrations_applied()`:
   - Owner is keel_owner and `search_path` is pinned to `pg_catalog, pg_temp`.
   - The table reference is schema-qualified and the body is static with no arguments, so there is no hijack or injection route.
   - But EXECUTE is the default PUBLIC grant: `has_function_privilege('public', ...)` returns true and `proacl` is NULL.
   - The function is created outside both the goose lock and the migration history. Concurrent migrators can race on CREATE OR REPLACE ("tuple concurrently updated"). A different migrating role fails with "must be owner".

   Fix: ship it as a kit migration that includes `REVOKE ALL ON FUNCTION ... FROM PUBLIC`. In deploy/db/postgres-roles.sql and testdb `grant()`, add `ALTER DEFAULT PRIVILEGES FOR ROLE keel_owner REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC` and grant EXECUTE to the app and operator roles. Add a test that a role without the grant is refused.
7. **internal/kit/migrate/validate.go:109-157, 196-251.** The statement splitter disagrees with goose. Goose ends a statement when the last word before `--` ends in `;`; Validate requires the trimmed line to end in `;`. I confirmed the following false negatives with an overlay test:
   - `create table a (..); -- note` followed by `drop table invoices;`: the drop is missed, and on MySQL two statements pass the one-statement rule.
   - Two statements on one line.
   - `truncate`.
   - `drop view`, `drop function` and other drops of non-table objects.
   - `add constraint ... foreign key|check` without `not valid`, which takes a locking scan on Postgres.
   - Dropping a unique constraint or index that a running `ON CONFLICT` depends on.
   - `alter column ... drop default`.
   - `vacuum full`.
   - A NOT NULL column whose check mentions the word `'default'`.

   Fix: split statements the way goose does, outside quotes and dollar quotes. Flip the check to a default-deny rule: every `drop`, `truncate`, `rename` and `alter ... type` is a contract change except `drop index concurrently`. Add a table row for each case above.
8. **internal/kit/testdb/postgres.go:192-206, mysql.go:200-210, testdb.go:240-255.** The janitor lists every database that starts with `<prefix>_t`, and `stale()` accepts any 14-digit segment. I verified that `keel_tenants_20250101000000` and `keel_test_backup_20260901120000` count as stale, so a superuser connection would drop them `WITH (FORCE)` on the developer's own server. Fix: match only the shapes testdb creates (`^<prefix>_t_\d{14}_[0-9a-f]{8}$` and `^<prefix>_tpl_[0-9a-f]{12}_\d{14}$`), and refuse non-loopback hosts without an explicit opt-in.
9. **internal/kit/paging/page.go:122-173, on reflection and D28.** `findField` ignores the table name for untagged fields. On a joined row such as `struct{ model.Customers; model.Invoices }`, which is the documented nested-struct pattern, `Invoices.ID` resolves to `Customers.ID`. I verified this: the cursor carried the customer id, which silently skips or repeats rows. On D28: the cache keeps the cost small, and Jet's qrm already reflects on every row. Speed is not the problem. Correctness is, and so is late failure: a missing field is a 500 on the first request, not a startup error. Fix: replace the reflection with typed accessors, `Sorts[R]` with `paging.By(col, func(R) V)`, which is compile-checked, unambiguous for joins and reflection-free. If reflection stays, match the embedded struct's type name to the table (Jet's own rule) and validate every sort against the row type at startup.
10. **page.go:175-200, keyset.go:150-163.** Cursor values are rebound as untyped text. A bool becomes `"true"`, and MySQL compares that to a tinyint as 0 (`SELECT 1 = 'true'` returns 0), so boolean sorts repeat rows on MySQL. `fmt.Stringer` is checked before the kind, so types whose `String()` is not their SQL form bind wrong. Fix: put a type tag in the cursor, bind native Go values, and prefer `driver.Valuer` over `Stringer`. This is subsumed if item 9 moves to typed accessors.
11. **internal/kit/ids/ids.go:104-110.** The zero id behaves three ways depending on the path:
   - `Value()` silently turns it into NULL.
   - `MarshalText` refuses it.
   - Jet's documented `UUID(id)` path writes `00000000-...` through `String()`, which `Scan` and `Parse` then refuse, leaving the row unreadable.

   Fix: `Value()` returns `errZero`. Optional references use `*ID[T]`. Stores bind through a helper that refuses the zero id.
12. **Missing tests for behaviour P4 relies on:**
   - A BeforeCommit error rolls the transaction back. D30 depends on this.
   - Begin hooks re-run on every retry attempt, and AfterCommit hooks from a failed attempt are dropped.
   - `ReadOnly()` refuses writes.
   - When retries run out, the original error is returned.
   - Kit migrations go Up, Down and Up again on both engines. The P2 done-when includes migrate on both engines, and only Current and Validate are exercised today.
13. **db.go:72-78, internal/app/commands.go:81.** In production the migrate URL silently falls back to the app URL. Under tenancy, the app role then owns the tables and can disable or unforce row-level security, which collapses the three-role model without any error. Fix: in production, require `MIGRATE_URL` whenever `OPERATOR_URL` is set, or have `Current` refuse when `current_user` owns a table in public. If deferred, record it in P4 doctor.
14. **cmd/keel/steps.go:56-62, .github/workflows/ci.yml.** There is no generated-code drift check, and P2 adds the first generated code. I ran `keel gen` in a copy and found no drift today. Fix: CI runs `keel gen`, then `git status --porcelain internal/dbgen`.

## Nits

15. **tx.go:213-215.** The `recover()` and re-panic do nothing useful, because the deferred Rollback runs during panicking anyway. Remove them.
16. **tx.go:167.** The AfterCommit append is not locked. Concurrent calls from goroutines inside fn race. Add a mutex or document the limit.
17. **tx.go:193-195.** If the context is cancelled during backoff, the database error is dropped. Return `errors.Join(err, ctxErr)`.
18. **lock.go.**
   - `Lock` fails inside a `ReadOnly()` transaction.
   - Under P4, names are global, so `invoices:number:2026` serialises every tenant. `Lock[Tenant]` should prefix the tenant id.
   - The table gains one row per name forever. Document this.
19. **internal/kit/migrate/locker.go:21.** `goose:` plus a database name longer than 58 characters exceeds MySQL's 64-character lock name limit (error 3057). Hash the name.
20. **testdb postgres.go:50.** The app role is set with `-c role=` on a superuser session. I verified `session_user=keel` is a superuser: `RESET ROLE` stays on the app role, but `SET ROLE` can escape. RLS follows current_user, so this is acceptable. P4 tests must assert on current_user and never use SET ROLE.
21. **testdb.go:209-229.** The template hash leaves out testdb's own grant logic, and current-hash templates never expire, so a change to `grant()` never reaches existing templates. Add a testdb version constant to the hash.
22. **paging/page.go:85.** `Offset{Page: (1<<62)+1, Limit: 4}.Skip(1000)` returns 0 with no error, because the multiplication overflows (verified). Compare with `o.Page > maxDepth/o.Limit` instead.
23. **keyset.go:136-143.** A cursor from one list is accepted by another list with the same sort key and a structurally equal filter (verified). Bind the cursor to a list name.
24. **internal/kit/db/db_test.go:179.** `time.Sleep(100ms)` breaks testing.md. Poll `pg_stat_activity` (`wait_event_type = 'Lock'`) or `performance_schema.data_lock_waits` instead.
25. **validate.go:112 and the CLI.** The contract marker is recognised only on line 1, so it cannot follow `-- +goose NO TRANSACTION`. Separately, the plan's `migrate version` is not exposed as a command.
26. **docs/tenancy.md section 3.** It names `deploy/roles.sql`; the file is `deploy/db/postgres-roles.sql`.
27. **Nullable sorts.** Jet emulates `NULLS LAST` on MySQL with an extra `IS NULL` key, which forces a filesort. On Postgres, the OR expansion for nullable sorts uses the index poorly. Document that nullable sorts are not index-backed.
28. **cmd/keel/gen.go:59, 141.** The scratch database name has one-second resolution, so concurrent runs collide. `charIDColumns` maps every `char(36)` column to uuid without checking for `ascii_bin`.
29. **ids.go:94-97.** `Scan` accepts an all-zero 16-byte value but rejects the all-zero text form.
30. **testdb.go:128-131.** Kit code reads env (hard rule 1), with a nolint. This is acceptable for a test-only package. Note it in packages.md.

## What I verified and how

- `go run ./cmd/keel check`: tidy, format, lint (0 issues), vet, govulncheck (none) and tests all green.
- `CGO_ENABLED=1 go test -race -count=1 ./...` uncached against Postgres 18.6 (5442) and MySQL 9.7.4 (3316): all pass in about 12s wall. The `-v` run confirms both engines ran. Only the Postgres-only role tests skip on MySQL.
- P2 adds about 4s of test time: the Postgres deadlock test takes 1.05s (deadlock_timeout), the paging walk 1.4s and the lock test 0.2s.
- Throwaway `go test -overlay` probes confirmed items 1, 2, 6, 7, 8, 9, 20, 22 and 23. MySQL bool coercion (item 10) was checked directly in mysql.
- Ran `keel gen` in a scratch copy and diffed internal/dbgen: no drift.
- `config:check` redacts all three URLs. Failed connections on both engines print the user and database but never the password.
- Read goose v3.29.0's provider: the session lock and migrations share one connection, and unlock uses a detached context. The MySQL GET_LOCK locker is therefore correct on connection loss: the server releases the lock when the session ends, and the in-flight migration fails on the same connection.
- Current (D32) matches the decision: pending files mean behind and are refused; unknown applied versions mean ahead and only warn. Down is refused in staging and production through `IsProd`.
