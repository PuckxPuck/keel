# P3a review (Opus)

Scope: internal/kit/{auth/realm,users,rbac,audit,ratelimit,occ,idempotency,webhook}, the httpx.go additions, internal/kit/db/transaction.go, the eight kit migrations on both dialects, and internal/app/{access,access_commands,build}.go. Measured against security.md sections 2 to 5, 10 and 11, architecture.md section 5, packages.md, D10, D17, D24, D29, D30 and D31, tenancy.md sections 1 and 5, and the conventions.

## Verdict: fix-then-ship

Need enforcement fails closed: an operation with no Need gets 403, a principal from another realm counts as nobody, the loader refuses disabled users, and it skips codes missing from the catalogue. The Postgres append-only grant works: the app role's ACL on `audit_log` is `ar` only, and UPDATE, DELETE and TRUNCATE are all refused. The MySQL `LAST_INSERT_ID` counter is exact under concurrency. The webhook spec vector passes.

Four things must change before merge:
- The audit hash chain forks under concurrency.
- `Verify` reports false breaks.
- The MySQL email column is accent-insensitive.
- The last access-manager rule can be bypassed and raced.

I reproduced items 1 to 3, 5, 6 and 14 with overlay tests on both engines.

## Blockers

1. **internal/kit/audit/audit.go:92-101 and store.go:52-65. The chain forks when the transaction read anything before `Record`.**
   - Cause: `lastHash` is a plain consistent read. On MySQL (REPEATABLE READ by default) and on Postgres under `db.Isolation(sql.LevelRepeatableRead)`, the transaction's snapshot predates the wait on the `audit:chain` lock. Two transactions therefore read the same prev hash.
   - Reproduced: 6 concurrent transactions, each doing a `SELECT` and then `Record`, end with `ErrChainBroken` on MySQL, and on Postgres under RR. Postgres READ COMMITTED passes.
   - This hits real flows: `users.SetStatus` (service.go:55) and `Access.Setup` (rbac/store.go:82) both read before recording. The existing chain test records with no prior read, so it cannot catch this.
   - Fix: keep the chain head in a row, for example `audit_chain(scope primary key, seq, hash)`. Read it with `SELECT ... FOR UPDATE`, which is a locking read, so MySQL sees the latest commit. Then `UPDATE` it. On Postgres RR a concurrent update raises 40001, which InTx retries.
   - Test: read before recording, on both engines and under RR.
2. **internal/kit/audit/redact.go:121-133. Canonical JSON is not stable across the jsonb and json round trip.**
   - Cause: `UseNumber` keeps numbers exactly as written. Go writes `1e+21` and `1.5e-07`. jsonb returns `1000000000000000000000` and `0.00000015`. MySQL returns `1e21` and `1.5e-7`.
   - Reproduced: one float field with an exponent makes `Verify` fail on both engines. Integers, `0.1`, `2.5`, uint64 max and `<>&`/U+2028 strings are fine.
   - Impact: `Verify` stops at the first break, so one such row hides every real tamper after it.
   - Fix: in `canonical`, render every `json.Number` as an exact decimal (parse with `big.Rat`, emit without an exponent or trailing zeros).
   - Test vectors on both engines: `1e21`, `1.5e-7`, `1E2`, `100.0`, `-0`, `1e-300`.
3. **db/migrations/mysql/20261022153753_kit_users.sql:4,10 with users/store.go:37-41. `email` inherits `utf8mb4_0900_ai_ci`, which ignores accents (and treats `ß` as `ss`).**
   - Reproduced on MySQL: creating `jose...@` and then `josé...@` gives `ErrEmailTaken`, and `ByEmail("josé...")` returns jose's user. Postgres keeps them distinct.
   - Impact: P3b keys sign-in, reset and OIDC linking on `ByEmail`, so an IdP-verified `josé@` would resolve to `jose@`'s account. This is the same class as the P2 locks blocker, and the file becomes append-only once merged.
   - Fix: `email varchar(254) character set utf8mb4 collate utf8mb4_bin not null`. Go already lower-cases the value.
   - Test: add accent and `ß` cases to the uniqueness test.
4. **internal/kit/rbac/guardrails.go:44-110, users/service.go:51-78, rbac/store.go:105-124. "The last holder of access management cannot be removed" is not upheld.**
   - (a) Disabling bypasses it. `SetStatus(Disabled)` has no guard, and the Loader refuses disabled users (rbac/store.go:202-204). Disabling the last holder, or disabling yourself, removes access management with no violation. There is no break-glass command (access_commands.go has only route:list, permission:list and setup), so recovery means SQL.
   - (b) Racy. The callers compute the facts (`OtherAccessHolders`, `Holders`, `HoldersElsewhere`, `OtherRolesWithAccess`) with no lock. Two admins removing each other at the same time both see 1 other holder and both commit.
   - (c) Undefined semantics. `SetUserRoles` counts only global grants (guardrails.go:112-116). `RolePermissionsChange` does not say whether holders must be active or hold the grant globally. So removing `access.manage` from the only global role passes when the other role carrying it is held only with a scope, or only by disabled users.
   - Fix:
     - The kit owns the fact queries and the write: `Access.SetUserRoles`, `SetRolePermissions`, `DeleteRole`, plus a disable guard that `users.SetStatus` must pass.
     - Each takes `db.LockIn(tx, "rbac:access:"+realm)`, counts only active users with a global grant in the realm, runs the pure guardrail, writes, and audits before and after.
     - Add an `access:grant` break-glass command.
     - Tests: concurrent mutual removal, disabling the last holder, holders that are only scoped or only disabled.

## Should-fix

5. **internal/kit/httpx/httpx.go:136-154. Hidden operations skip every startup check.**
   - Cause: `Operations` reads the OpenAPI paths, and Huma never adds `Hidden` operations to them (huma.go:816).
   - Reproduced: `Build` accepts a hidden op that has no Need and no class. Enforce still answers 403, but `limiter.take` lets an empty class through (limiter.go:168-171), so rate limiting fails open. route:list and the walk test also miss the op.
   - Fix: `Register` records every op in its own per-API registry, and `Operations` reads that registry. `take` should refuse an undefined class at runtime.
6. **internal/kit/idempotency/middleware.go:107. The request hash leaves out the query string.**
   - Reproduced on both engines: `POST /pay?amount=1`, then `?amount=9` with the same key, replays the first 200 with `Idempotent-Replayed: true`.
   - Fix: hash the method, the realm, the path, the canonical `RawQuery` and the body. Update packages.md. Document that header params are not covered.
7. **middleware.go:128-135. A 5xx, or a failed `finish`, frees the key, so the retry runs the change twice.**
   - After `db.ErrCommitUncertain`, the commit may have landed. `finish` can also fail after a successful 2xx: the MySQL `mediumblob` caps at 16 MiB, or the database can blip. In both cases `release` deletes the key and the client's retry executes the change again.
   - idempotency_test.go:117-122 currently asserts this behaviour.
   - Fix: release only on 4xx. On 5xx, keep the claim until abandonment, or store the response. If `finish` fails, leave the row in progress. Cap the stored body; when it is over the cap, store the status with a marker.
8. **idempotency/store.go:20-23, 46-48, 114-116. An abandoned claim can be taken over while its request is still running.**
   - The comment's premise is false: `WriteTimeout` does not stop a Go handler. A request held up past 2 min (lock waits, heavy work) is taken over and runs twice. The first request's `finish` then updates a vanished row id, and nothing notices.
   - Fix: run the handler under `context.WithTimeout(abandonAfter - margin)`. Check `RowsAffected` in `finish`.
9. **middleware.go:178-186. The caller key is `u:<id>` with no realm, and later no tenant.**
   - Users are global identities. In P4 the same user and key, on the same path and body, in tenant B would replay tenant A's stored response.
   - Fix: build the key as realm plus user now. Add the tenant in P4, and make `tenant_id` part of the unique key.
10. **webhook_deliveries is keyed by `id` alone (postgres 20261022153804:3, mysql 20261022153805:3; webhook.go:151-168).**
    - Two senders, or one provider fanning a message id out to two endpoints, would have the second delivery dropped as a replay.
    - tenancy.md requires tenant-scoped keys. Changing a primary key later is a contract migration, not an expand migration.
    - Fix now: add a `source` column, make the primary key `(source, id)`, and change the call to `Seen(ctx, tx, source, id)`.
11. **webhook.go:91-97. Verification work is amplified.**
    - The HMAC over the whole body is recomputed for every (signature, secret) pair. About 45 `v1,` entries fit in 2048 bytes, so one unauthenticated 1 MiB request with 2 secrets costs about 90 MiB of HMAC.
    - Fix: compute one MAC per key before the loop, and cap the number of parsed signatures (for example 8).
12. **ratelimit/limiter.go:140-148, 151-164. `PreAuth` and `HTTP` ignore `FailClosed`.**
    - When a fail-closed store fails, `take` returns `(Allowed: true, ok: false)`. Both paths only refuse on `ok && !d.Allowed`, so the request goes through.
    - Fix: answer 503 on `!ok`, as `Middleware` does. Test with a failing store.
13. **limiter.go:25-30 with dbstore.go:41. DBStore rules default to fail-open.**
    - D31's security counters let sign-in and MFA attempts through when any of these happen:
      - a database blip;
      - the 2 s timeout, which an attacker can trigger with lock contention on one key;
      - an upsert deadlock.
    - Fix: make DBStore-backed rules fail closed by default (for example `Define` panics when the store is a `*DBStore` and `FailClosed` is false, or invert the flag). Retry once on a deadlock.
14. **rate.go:82, limiter.go:66, internal/app/build.go:82. Health probes are throttled.**
    - Reproduced: the 61st `/livez` in a minute from one address gets 429.
    - Impact:
      - Kubelet and Docker count 429 as a failed probe, and a failed liveness probe restarts the container.
      - Every probe from one address shares a bucket. Behind an untrusted local proxy, external clients share the loopback bucket too, so anyone can trigger restarts.
    - The limit protects nothing: `/livez` does no work, and `/readyz` is cached for 5 s and never runs concurrently.
    - Fix: no limiter on `/livez`. For `/readyz`, none or a generous `ByNetwork` default.
15. **audit/store.go:53, audit.go:76. The chain is not ready for P4.**
    - Under row-level security on `audit_log`, a tenant transaction sees only its own rows. Its `prev_hash` then points at its own tenant's last row while `seq` interleaves tenants, so `Verify` on the operator pool breaks.
    - The single global lock also serialises every audited write in every tenant.
    - Fix: with item 1, keep one chain head per scope (a tenant, or global), and verify per scope.
16. **audit/redact.go:41-50, 71-74. Redaction has gaps.**
    - Any value whose type has `MarshalJSON` or `MarshalText` is kept whole, so `audit:"redact"` tags inside it are ignored, and a secret type with its own marshaller prints its value.
    - Maps with non-string keys are returned unscrubbed.
    - `map[string]any` images get no redaction by key name, although logx already has a list of known keys.
    - Fix:
      - Scrub only an allowlist of marshaller types whole (time, uuid, ids, `config.Secret`).
      - Stringify map keys the way encoding/json does, then scrub the values.
      - Reuse logx's key list for map keys.
17. **rbac/principal.go:66-67, need.go:94-103. A scoped grant passes `Requires(P)` on any target.**
    - If a service forgets `CanIn`, the scope is silently ignored. The scope feature fails open.
    - Fix: `Requires` means a global grant. Add `RequiresIn(P)` for operations whose service checks the scope, and list those operations in the walk.
18. **internal/app/access_test.go:67, 74, 81. The permission walk is weak.**
    - Gaps:
      - It skips any write whose Need has no permissions, so `Public` and `SignedIn` writes are never questioned.
      - It only tries a principal with no permissions, so an all-of check implemented as any-of would pass.
      - It has no anonymous (401) case and no other-realm case.
      - It asserts `walked == 3`, which breaks on the app's first write.
    - Fix: walk every unsafe operation:
      - `Public` writes must be on an explicit allowlist.
      - `SignedIn`: anonymous gets 401.
      - `Requires`: dropping each permission in turn gives 403.
      - `RequiresAny`: holding any single one passes.
      - Assert `walked >=` the fixture count.

## Nits

19. **audit/store.go:118-144. The limits of `Verify` are undocumented.** The SHA-256 chain has no key, so a truncated tail, or a full rewrite by the owner role with recomputed hashes, goes undetected. Rows inserted with a NULL hash are skipped. Document this, and periodically log the head `(seq, hash)` as an anchor.
20. **users/store.go:70-80, users_test.go:79. `current()` never fills `ChangedBy`.** The test is named "with who and when" but asserts neither. Add `updated_by`, or rename the test.
21. **user_roles `granted_by` (postgres :8, mysql :16) has no `on delete` action, while `user_id` cascades.** Deleting a user who ever granted a role fails. Use `on delete set null`.
22. **The same migration has different versions per dialect:** role_permissions is 153756 on Postgres and 153757 on MySQL; webhook_deliveries is 153804 and 153805. Align them.
23. **auth/realm/realm.go:127-134. IDN hosts are not converted.** A configured `bücher.example` never matches the punycode `Host` that clients send. Use `idna.Lookup.ToASCII` in `New`, or refuse non-ASCII hosts.
24. **idempotency/middleware.go:85. `LimitReader(body, -1)` reads nothing.** On an operation with no body limit, the handler silently receives an empty body. Refuse `Required()` on unlimited operations.
25. **ratelimit/dbstore.go:45-58 has no default dialect branch.** An unknown dialect counts 0 hits and always allows. Return an error.
26. **ratelimit/keys.go:52-55. Every request without a client IP shares the `unknown` bucket.** For example, a unix socket behind a proxy that is not trusted. One client can then exhaust the auth class for everyone. Add a doctor or startup warning.
27. **ratelimit/memory.go:79-96. Eviction scans the whole shard under the lock for every new key while the store is full.** That is fine at the default 50k keys and costly at 1M. Consider sampled eviction.
28. **audit/audit.go:43-49. `ActorFrom` defaults to system even inside a realm request.** If P3b's resolver misses `WithActor`, user actions are recorded as system. Refuse or flag that case when `httpx.Realm(ctx) != ""`.
29. **rbac/store.go:81-88. `Setup` recreates a built-in role that an admin deleted** on the next deploy. Document this, or keep a tombstone.

## Fix pass (2026-10-22)

Blockers 1 to 4 were reproduced with failing tests first (chain fork after a prior read under repeatable read, float round trip, accent collision on MySQL, disabling the last manager).

1. Fixed. New `audit_chain` head table (key `global`), created on first use and read `FOR UPDATE`, moved in the same transaction; the `audit:chain` lock is gone. Test: 8 concurrent chained writes, each reading first, under repeatable read on both engines.
2. Fixed. Canonical JSON writes every number as an exact decimal without exponent; vectors `1e21`, `1.5e-7`, `1E2`, `100.0`, `-0`, `1e-300`, `-12.50`, uint64 max survive jsonb and MySQL json. Integers beyond 64 bits and decimals beyond float64 precision are documented as needing strings.
3. Fixed. `utf8mb4_bin` on MySQL, exact unique index on Postgres, NFC normalisation in Go.
4. Fixed. Access writes and `users.SetStatus` take the actor, lock `rbac:access:<realm>`, count only active users with an unscoped grant via locking reads, and refuse inside the kit; `app user:grant` is the break-glass (system actor, realm-checked, audited). Concurrent mutual removal and mutual disabling leave one manager.
5. Fixed. `httpx` keeps its own registry fed by a group modifier, so `Operations` includes hidden ops; every startup check uses it; an undefined class refuses at runtime.
6. Fixed (query, content type and path in the hash; header params not covered, documented).
7. Fixed. Nothing is released: 2xx and 4xx are kept, 5xx and failed saves leave the outcome unknown.
8. Fixed. No takeover: past the lease the key is 409 `idempotency_outcome_unknown` until expiry; `finish` checks rows affected. The handler is not given a timeout (no takeover makes it unnecessary).
9. Fixed. Realm in the key; P4 adds the tenant.
10. Fixed. `(source, id)` primary key, `v.Seen(ctx, tx, id)`.
11. Fixed. One MAC per secret, at most five signatures compared.
12. Fixed. 503 on `!ok` in `PreAuth` and `HTTP`.
13. Fixed. Every store fails closed unless `Rule.FailOpen`; `DBStore` retries a deadlock once.
14. Fixed. Health class skips loopback clients and trusted proxies on loopback or a trusted unix socket (`httpx.LocalProbe`); default `6000/1m` otherwise.
15. Fixed with 1: one head per chain key; P4 adds per-tenant keys and verification.
16. Fixed. Structs walked whatever their marshalling; other marshallers `[opaque]` unless `audit.Redactable` or known safe (time, uuid, ids, dates, money, `config.Secret`); non-string map keys stringified; map keys `logx` treats as sensitive are redacted (`logx.Sensitive` exported for this).
17. Fixed. `Requires` and `RequiresAny` need unscoped grants; `RequiresIn(p, scopeFrom)` with `rbac.PathScope` for scoped access.
18. Fixed. The walk derives operations from the registry (hidden included), checks anonymous 401, other realm 401, signed-in writes, each single permission for `RequiresAny`, drops one permission at a time for `Requires`, keeps an allowlist for public writes, and asserts `walked >=` the fixture count.
19. Documented in packages.md and security.md; `Verify` also checks the head against the last row, which catches a deleted tail. No periodic anchor job (jobs are P5).
20. Fixed. `users.updated_by`, set by `SetStatus`, reported as `changedBy`.
21. Fixed. `granted_by ... on delete set null` on both engines.
22. Fixed. Versions aligned (role_permissions 153756, webhook_deliveries 153804).
23. Fixed. Configured hosts go through `idna.Lookup.ToASCII`; request hosts in Unicode are converted too.
24. Fixed. `idempotency.Check` refuses a marked operation without a body limit.
25. Fixed. Unknown dialect is an error.
26. Not done: a startup or doctor warning for the shared `unknown` bucket belongs with `app doctor` (P6), which knows the listener and proxy trust.
27. Fixed. Eviction looks at a sample of 64 buckets.
28. Not done: P3b's session resolver sets the actor; whether an anonymous realm request should record a distinct actor type is its decision.
29. Documented (Setup recreates a deleted built-in role).
