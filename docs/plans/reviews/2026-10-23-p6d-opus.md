## Blockers
**B1. `keel compat` fails in every app clone without keel's tags.** `cmd/keel/compat.go:115`.
- Scenario: the documented flow (`docs/cli.md`, init section) is clone, checkout tag, init, commit. Pushing to the app's own remote does not push tags by default.
- Any later clone, including CI's `fetch-depth: 0` compat job (`.github/workflows/ci.yml:41-57`) and `keel check` locally, hits `rev-parse v0.1.0` failing. The step then errors with ".keel-version names v0.1.0, which this clone does not have". Reproduced on a committed app after `git tag -d v0.1.0`: exit 1.
- The app's PR CI is red from its first PR.
- Fix: when the clone is not shallow and the `.keel-version` commit is absent, keel's tags are absent too, so there is nothing to exclude. Return no tags (and perhaps print a note) instead of failing. Keep the error only for shallow clones (line 91 already detects them). Add a test.

## Should-fix
**SF1. Ctrl-C does not roll back.** `cmd/keel/init.go:114` and `:178-179`.
- Scenario: `resetTree` runs with the cancelled signal context, so `exec.CommandContext` refuses to start git. Reproduced: SIGINT during `go build` printed "reset failed ... context canceled". It left 412 changed paths and a `.keel-version`, so a rerun is refused as "already run".
- Fix: `resetTree(context.WithoutCancel(ctx), ...)`.
- Also add a rollback test (failing step: tree back at HEAD, an ignored file kept) and a cancelled-context case. Today nothing tests the failure path.

**SF2. Client trace headers decide sampling.** `internal/kit/otelx/otelx.go:130`.
- otelhttp extracts the inbound `traceparent`, and the sampler is `ParentBased`.
- Probe: a request with `traceparent: ...-01` produced a span whose parent and trace id were the attacker's. Any client can force 100% sampling (exporter cost) and plant trace ids that then show in logs through `LogAttrs`.
- Fix: `otelhttp.WithPublicEndpoint()`, or `WithPublicEndpointFn` trusting only internal callers, so inbound context becomes a link.

**SF3. Host header sets metric cardinality.** `otelx.go:130`.
- otelhttp labels `http.server.request.duration` with `server.address` taken from `req.Host`. Random Host values fill the SDK's 2000-series limit, and metrics collapse into the overflow series.
- Fix: `otelhttp.WithServerName(service)`.
- While there, add `otelhttp.WithFilter` to skip `/livez` and `/readyz`. The probe shows health checks traced.

**SF4. upgrade:diff output never applies cleanly after a module rewrite.** `cmd/keel/upgrade.go:88`.
- Init always rewrites kit import paths. It also rewrites `cmd/keel/database.go` for `--name`.
- Reproduced: a one-line kit change next to an import failed `git apply --check`.
- `docs/operations.md:173` documents "rewrite them yourself". The tool knows both paths, so piping the diff through the same module rewrite is cheap and removes a manual, error-prone step.
- Fix: read the app's `go.mod` and rewrite keel's module path in the output.

**SF5. A no-tenancy app still provisions a BYPASSRLS login.**
- `deploy/db/postgres-roles.sql:14-42` (`<name>_operator LOGIN BYPASSRLS`, grants, required `operator_password`), `deploy/db/local-init.sh:8` and `docker-compose.yml:14` survive `--without tenancy` (checked in `initrun-pgall`). The marker grammar has no `--` form for SQL.
- That is a privileged role with DML on every table that nothing uses: a least-privilege regression for the operator who runs it.
- Fix: move the operator role into its own file owned by the tenancy part, or add `-- part:x` markers.

**SF6. Nothing tests that tracing keeps the tenant reset.** `internal/kit/db/db.go:256-261`.
- `Connector` documents that the wrapped pool must keep `ResetSession`, and today it does (my probe passed). But nothing tests it. A future otelsql option or upgrade could leak `app.tenant_id` across borrowers, and only with tracing on.
- Fix: keep the probe as a test in `otelx`: open with `ResetTenant` plus `Connector(OpenDB)` and `MaxOpen 1`, run a session `set_config`, release, re-borrow, and assert empty.

**SF7. A job span records raw error text.** `otelx.go:183`.
- `span.RecordError(err)` exports `err.Error()` to a third-party collector. SMTP and webhook errors carry recipient addresses and URLs.
- Fix: set the status with a fixed message and record only the error type, or the outcome class.

**SF8. Preflight does not check reachability when the URL comes from the environment.** `init.go:168-171`.
- `e.url` returns `APP_TEST_DATABASE_URL` unchecked. With an unreachable URL, init writes the whole plan, builds and then resets (I reproduced this). `docs/cli.md` says init "refuses a database it cannot reach".
- Fix: dial or ping in preflight.

**SF9. The matrix never runs `--env-prefix`.** `.github/workflows/init-matrix.yml:33-40`.
- The prefix rewrite is the widest text edit init makes, and no CI job runs it. My local run passed.
- Fix: add one row (`--env-prefix SHOP_`), or fold it into an existing row.

## Nits
- `db/migrations/embed.go:18`: in an app, `For(otherDialect)` returns an empty FS without error, so pointing an app at the wrong engine gets past `CheckCurrent` on an empty database. Return an error when the directory is absent.
- `otelx.go:208`: `LogAttrs` stamps trace ids for unsampled spans, which are never exported. Gate on `sc.IsSampled()`.
- `otelx.go:57`: `Endpoint` may carry userinfo and is a plain string (printed by `config:check`). Refuse userinfo, or make it a `Secret`.
- `AGENTS.md:5` (and the README intro) still tell an app "keel is a Go backend template". Mark it `part:keel` or rewrite it.
- Every app keeps `internal/app/notes_off.go` and the `notesModules` hook for keel's example module. Consider dropping the twin and the call for module parts.
- `cmd/keel/parts.go:300`: `APP_NAME` is exempt from the prefix rewrite because `release.sh` uses it, but it is also the app's own setting (`config.App.Name`, `env:"NAME"`). The collision is latent; rename `release.sh`'s variable.
- After a `--name` rewrite, a still-running keel compose Postgres on 5442 blocks the app's `make up` and rejects the new `shop` user. Add one line about that to init's closing message.
- `cmd/keel/init_test.go:155`: `TestInit_EndToEnd` is 75s of the local check. Gate it behind `-short` in `make test`, since init-matrix covers it on main.
- Optimization: run `go test -tags <all-off> ./internal/app/...` (7s) in PR CI, so off-twin runtime drift is caught per PR instead of nightly. Note it runs against the full schema.

## Fix pass (init and tooling)
- **B1** fixed (`cmd/keel/compat.go`). When `.keel-version` names a commit the clone lacks and the clone is not shallow, nothing is excluded: compat compares against the app's own latest `v*` tag, or skips with "no release tag of the app yet". A shallow clone is still an error. Tests: an app clone without keel's tag (skip), the same with its own `v1.0.0` (compared), and a shallow app clone (error).
- **SF1** fixed (`cmd/keel/init.go`, `initplan.go`, `scaffold.go`). `applyInit` resets the checkout on `context.WithoutCancel(ctx)` after any failure from the first write on: `commitAll` included, and interrupts. `--keep-on-failure` keeps only a failed step's result, never an interrupted one. The undo journal records each deleted file's mode. Tests:
  - `TestApplyInit_RollsBack`: a delete fails midway through the commit; a step is cancelled with `--keep-on-failure` set. Both end with `git status` clean, `.env` kept and an executable's 0755 mode back.
  - `TestCommitAll_UndoKeepsModes`.
- **SF4** fixed (`cmd/keel/upgrade.go`). The diff's module path is rewritten from the checkout's `go.mod` to the app's, in plain and regex-escaped form. `TestUpgradeDiff_AppliesAfterModuleRewrite` runs `git apply --check` on a renamed app. The name rewrites (`cmd/keel/database.go`'s local URL) are not redone; `docs/cli.md` says so.
- **SF5** fixed. There is a new SQL marker form, `-- part:x` / `-- /part:x`. In `deploy/db/postgres-roles.sql`, the operator password check, `CREATE ROLE`, drift repair, `CONNECT`, schema usage and default privileges all sit inside `part:tenancy`; the drift repair is split per role. `local-init.sh` builds its psql arguments with `set --`, so the operator line is a whole-line block. Compose's `KEEL_OPERATOR_PASSWORD` is marked too. Checked in throwaway `postgres:18.6` containers:
  - full script: three logins;
  - stripped script: no `keel_operator` and no operator grants;
  - drift is repaired on a rerun, and a missing `operator_password` is still refused.
- **SF8** fixed. Preflight connects with `db.OpenSQL` (10 s bound) to the URL gen will use, environment or compose default, before anything is written. There is a test case in `TestInitPreflight_Refusals`.
- **SF9** fixed. `init-matrix.yml` has a "postgres, every part, settings prefix" row (`--env-prefix SHOP_`). The scratch `runall.sh` already had one.
- Nits:
  - `TestInit_EndToEnd` is kept. It now asserts only what the plan tests cannot (the written app builds and vets, `.keel-version` on disk), and it runs with `--env-prefix SHOP_` so the prefix rewrite is compile-checked on every check. It is still skipped under `-short`.
  - The `APP_NAME` collision is fixed: `release.sh`'s `APP_NAME`, `APP_USER` and `APP_ROOT` are now `DEPLOY_NAME`, `DEPLOY_USER` and `DEPLOY_ROOT`. Also updated: `deploy/test/switch_test.go`, `docs/operations.md`, and `envNotPrefixed`, which is now only `APP_TEST_`. `make deploy-test` passes (systemd mode).
  - The compose port clash is covered: init's closing message tells the user to stop keel's containers (`docker compose -p keel down`) before `make up`.
  - `AGENTS.md` keeps its template sentence in a `part:keel` block. Its kit sentence now reads the same in keel and in an app.
- Also from this pass: `cmd/keel/parts.go` lists the new `internal/app/tenancy_off_test.go`. `partsOwning` skips `_off_test.go` as it skips `_off.go`.
