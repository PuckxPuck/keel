# P5b review (Opus)

Scope: internal/kit/{files,files/inspect,fileshttp,xlsx,barcode,pdf,csvx,docx}, internal/kit/paging/feed.go and feed_test.go, the kit_files and kit_tombstones migrations on both engines, and the doc edits that go with them.

## Verdict: fix-then-ship

Storage, the service flow and the feed are well built. The details hold up:
- Local storage goes through os.Root and fsyncs the file and its directories.
- Uploads spool under a +1 cap.
- The object is written, the row recorded, and the delete deferred to AfterCommit.
- The sweep is prefix-scoped, batched and guarded by a minimum age.
- On Postgres the feed uses the xid8 and snapshot-xmin watermark, merges with tombstones correctly, and uses domain-separated HMAC tokens.

The PDF inspector does not deliver what security.md section 6 promises. I built nine PDFs that hide JavaScript from it, and inspect returns nil for all nine. The fix is a redesign of the scanner, not a tweak.

## Blockers

1. **internal/kit/files/inspect/pdf.go:57-169: the PDF scanner fails open.** I ran each case below through `Detect` and then `Inspect` using a `go test -overlay` probe. Each hides `/S /JavaScript` in an object stream or behind it, and every one returned `err=<nil>`:
   - **Indirect filter.** `/Filter 3 0 R` makes the stream read as raw (pdf.js resolves the reference).
   - **Abbreviated filter names.** `/Filter /Fl` and `/Filter /AHx` are not in `opaqueFilters` and are not `FlateDecode`, so the stream reads as raw. pdf.js accepts both names.
   - **Image disguise.** If the dict says `/Subtype /Image` and omits `/Type /ObjStm`, then `image` is true (line 147). Flate content is then inflated and discarded unscanned (158-160), and the opaque-filter refusal is skipped (149). pdf.js does not check `/Type` on object streams.
   - **Image `/Length` skip.** A raw image stream whose `/Length` covers the following objects makes `br.Discard` (164) jump over a plain `<< /S /JavaScript >>` object. Readers locate objects by xref, not by stream length.
   - **PNG predictor.** `/DecodeParms << /Predictor 12 >>` inflates to row deltas, so the scanned bytes never spell the name.
   - **Literal-string reset.** `/X (obj)` inside the stream dict tokenises as `obj`, which calls `reset()` (112). The scanner forgets `/FlateDecode` and reads the stream as raw. Strings are not skipped as strings anywhere.
   - **XFA.** `/AcroForm << /XFA ... >>` carries `<script>` in XML. `XFA` is not refused, and the script never appears as a PDF name.

   The doc's claim that "streams in other encodings are refused" (security.md section 6) is false for the first four cases. The existing test "javascript in a compressed object stream" (inspect_test.go, `pdfStream(... flate(...))`) does not exercise inflation: zlib of that 28-byte payload still contains `/JavaScript` in clear (I checked), so the test passes with or without inflate.

   Fix: make the scanner fail closed.
   - Skip literal strings (nesting and escapes) and hex strings as tokens.
   - Parse each stream's dict for `/Filter`, `/DecodeParms` and `/Length`, and refuse an indirect reference on any of the three.
   - Inflate and scan only when the filter is a direct `FlateDecode`, or an array of only that, with no predictor (or implement the PNG and TIFF predictors).
   - Accept `DCTDecode`, `JPXDecode`, `CCITTFaxDecode` and `JBIG2Decode` without decoding, but scan the raw bytes up to `endstream`. Never skip by `/Length`.
   - Refuse any other filter name, abbreviations included.
   - Add `XFA` (and arguably `RichMedia`) to `pdfRefused`.
   - Add a corpus row for each bypass above, using a compressible payload of 1 KiB or more, and assert that the compressed bytes do not contain the name.
   - Or swap in a real parser such as pdfcpu, which resolves object streams. Either way, record the choice in stack.md.

## Should-fix

2. **internal/kit/paging/feed.go:132, 280-283: tombstones can be pruned before they are delivered.** On a caught-up page, `since` is `w.opened`, but the window only reached `until = opened - Lag` (MySQL), or xmin (Postgres, which is held back by open transactions). On MySQL, a tombstone with `deleted_at` in `(S - Lag, S]` is not yet delivered. A client returning at R, with `S + Retention - Lag < R <= S + Retention`, passes the retention check, yet the prune job has already deleted that tombstone. On Postgres the window is the deleting transaction's duration, because `deleted_at` is app time at `Tombstone()` and not commit time. The result is a missed delete with no resync. Fix: use `Since = until` on MySQL and `opened - maxTx` on Postgres, or have Open reject at `Retention - margin`. Document that PruneTombstones' `before` must be `now - Retention`.
3. **internal/kit/files/store.go:113-145, service.go:212: anyone can claim a staged file.** Staged rows record no uploader, so any user who learns a staged id can `Attach` it to their own record and then download it through their own permission. `Authorize` also has no way to decide who may read a staged file. Fix: add a `staged_by` column now (nullable, an opaque actor string set from the context), and require a match in `attachFile`.
4. **internal/kit/files/service.go:200-208: Stage trusts `Object.Key`.** Object is a plain exported struct. An app that round-trips it, for example a two-step upload, lets a client stage `assets/logo` or another prefix. A later `Remove` then deletes an object this package never made, and `Open`'s prefix check (251) passes because the prefix is empty. Fix: in Stage, require `validKey(obj.Key) && HasPrefix(obj.Key, KeyPrefix(ctx)+objectDir)`, and use `+objectDir` in Open too. Unexported fields would be better still.
5. **internal/kit/files/storage.go:202-233 with service.go:119: flat key directory.** Every key is `f/<32 hex>`, so the Local driver keeps one directory with every file. `fs.WalkDir` reads and sorts the whole directory before the first callback, so with a million files the sweep holds the full listing in memory, which breaks the "never everything in memory" lesson. Fix: shard the keys (`f/ab/cd/<hex>`).
6. **internal/kit/files/sweep.go:37, 60, and Config: a shared bucket is unsafe.** Two apps or environments pointed at one bucket both own `f/`, and each one's sweep deletes the other's objects as orphans, because the other database has no row for them. Fix: add an `APP_FILES_KEY_PREFIX` (an app namespace) to Config, prepended to KeyPrefix. At minimum, configuration.md should state one bucket per app per environment.
7. **internal/kit/files/inspect/zip.go:225-268: XLM macro sheets pass.** I probed an xlsx with `xl/macrosheets/sheet1.xml`, content type `application/vnd.ms-excel.macrosheet+xml` and relationship `.../xlMacrosheet`, and it returned TypeXlsx with no error. Excel should refuse macro sheets in a non-macro workbook, but the check is cheap. Fix: add `macrosheet` to both deny lists. That covers `xlMacrosheet`, `xlIntlMacrosheet` and `macrosheet+xml`.
8. **internal/kit/files/inspect/image.go:23-30, inspect.go:65: image memory.** At the default 50 Mpx, a 16-bit PNG decodes to NRGBA64, which is 400 MB. At the default concurrency of 2, that is 800 MB before encoding. Fix: budget decoded bytes using `cfg.ColorModel` (8 bytes per pixel for the 64-bit models), or lower the default to 16 to 24 Mpx.
9. **No HTTP upload path.** Streaming is guaranteed only from `Service.Put` on. Huma's multipart handling and `r.FormFile` (via ParseMultipartForm) keep up to maxMemory in RAM and spill to the OS temp dir, which bypasses TempDir. Before wiring, add a fileshttp upload helper over `r.MultipartReader()` with `http.MaxBytesReader`, or document the pattern in packages.md.

## Nits

- **zip.go:32-49.** The header pre-check can be dodged. The EOCD count is 16-bit and archive/zip compares only modulo 65536, and the directory size is never checked against the EOCD offset. I confirmed this with a 65,539-entry zip that claims 3: it is caught only by the post-check, after archive/zip has built every `File`, which costs roughly 4 to 5 times the upload in memory. Requiring `dirOffset + dirSize == eocdAt` (or the zip64 equivalent) makes the header numbers binding.
- **zip.go:171.** A nested archive is detected only by `PK\x03\x04` at offset 0, so an inner zip with one junk byte prepended is not walked. Zip entries that are PDFs or images are not inspected either. Say so in the doc.
- **inspect.go:177-185.** If the underlying Read returns `(0, nil)` at budget 0, the next `Read(p)` is unbudgeted. Loop until n > 0 or err.
- **service.go:158.** A re-encoded image can grow past `policy.MaxBytes`, so check `cw.n` again.
- **sign.go:41, service.go:259.** The TTL has no cap. The signed message is the id and expiry, with no tenant. See P4.
- **disposition.go:15.** RFC 6266 appendix D advises keeping `%` out of the ASCII fallback, so map it to `_`.
- **fileshttp.go:36-73.** A nil `Authorize`, `Load` or `Signer` panics per request. Validate at construction.
- **csvx.go:34.** Add the small-form variants U+FE62, U+FE63, U+FE66 and U+FE6B.
- **xlsx.go:312, 322.** `decimal` becomes `InexactFloat64`. The cell is a double either way, but AGENTS rule 12 says no floats near money. Document that money columns go out as `csvx.Number` of minor units, or as text.
- **files_test.go TestStorage_Contract.** It never asserts that SSE was applied (HeadObject `ServerSideEncryption`).
- **sweep.go:44.** There is no floor on MinAge. A caller passing one minute can sweep objects whose Stage transaction is still open.
- **docker-compose.yml:59.** Gotenberg allows `file:///tmp/.*` with JavaScript on, so injected HTML can read other renders under /tmp. Consider `--chromium-disable-javascript` and a narrower list. deploy/ has no Gotenberg config yet.

## P4 tenancy readiness

The stores take `db.Transaction` and never name the tenant, so RLS and the column default slot in without rewriting queries. P4 must touch the following:
- **files.** Add `tenant_id` with RLS, make `storage_key` unique per tenant, and widen the indexes.
- **tombstones.** PK `(tenant_id, entity, id)`, feed index `(tenant_id, entity, change_xid|changed_at, id)`, and the `Tombstone()` ON CONFLICT target.
- **KeyPrefix wiring.**
- **URLSigner.** It must sign the tenant id. `fileshttp.Public` is unauthenticated, so it cannot find an RLS row without one.
- **Feed tokens.** Bind the tenant into the token.
- **Sweep.** The key layout `<tenant>/f/<rand>` forces one List and one runner per tenant. Prefer `f/<tenant>/<rand>`, which lets a single operator-pool sweep cover every tenant while keeping the per-tenant prefix check.

## Fix pass

1. **PDF scanner fails open: fixed.** pdf.go is rewritten to fail closed with no new dependency. The top level is tokenised: literal strings with nesting and escapes, hex strings, comments, and names with #xx. Each stream dictionary is parsed into values.
   - Refused: indirect `/Filter` or `/DecodeParms`; any filter other than full-name `FlateDecode`; `DCTDecode`, `JPXDecode`, `CCITTFaxDecode` and `JBIG2Decode` except as the last filter of a dictionary that is exactly an image XObject (`/Subtype /Image`, `/Type` absent or `XObject`, no `/N` or `/First`); `/F`, `/DP`, `/FFilter` and `/FDecodeParms` on a stream, since pdf.js reads `/F` and `/DP` as Filter and DecodeParms.
   - Length: a direct `/Length` must land on `endstream`, and `endstream` inside the data is refused. Flate is self-delimiting when the length is indirect, and raw data runs to the first `endstream`, which is where pdf.js ends it.
   - Decoding: every Flate stream, images included, is inflated within the budget, with PNG predictors and TIFF predictor 2 (8 and 16 bit) undone. Every name in decoded data is checked wherever it sits, and a `>> stream` inside decoded data is refused.
   - Opaque bytes (strings, comments, stream data) are refused when they hold an object header (`<digits> obj`) or `startxref`. A reader following the cross-reference table could parse those bytes, though the tokeniser does not.
   - Names refused: XFA, RichMedia, GoToR, GoToE, SubmitForm and ImportData were added.

   All nine of your bypasses are corpus rows, plus a hidden object in a string, a stream hidden in an object stream, and a length that does not end at `endstream`. Twelve PDF rows fail on the previous scanner. The compressed object stream payload is 1.5 KiB, and the test asserts the zlib bytes do not contain `JavaScript`. A clean PDF with an indirect-length Flate stream, a JPEG image and a predictor-12 xref stream passes. 90 s of fuzzing found nothing. security.md section 6 now lists exactly what is refused.
2. **Early tombstone pruning: fixed.** A caught-up token's `Since` is now `opened - Lag` on both engines, and so is a fresh sync's. On Postgres, `Lag` is documented as the longest-transaction bound. PruneTombstones is documented as taking `now - Retention`. New test TestFeed_CaughtUpTokenExpiresLagEarly fails on the old code.
3. **Anyone could claim a staged file: fixed** by the new lifecycle. Rows record `uploader_kind` and `uploader_id`. Stage and Attach require the same uploader; `files.SystemUploader` may attach any staged file.
4. **Stage trusted Object.Key: fixed.** Object is gone, and Stage takes a file id and an uploader, no key. Open, Remove and Sweep only act on keys from rows the package wrote, or on keys in its exact layout under its prefix.
5. **Flat key directory: fixed.** Keys are `<prefix>f/<ab>/<cd>/<32 hex>`. Local.List walks with `ReadDir(256)` batches instead of WalkDir.
6. **Shared bucket: fixed.** `APP_FILES_KEY_PREFIX` (validated) namespaces every key, and Sweep lists only under `<prefix>f/`.
7. **XLM macro sheets: fixed.** Refused by content type (`macrosheet`, including `intlmacrosheet`), by relationship type (`xlMacrosheet`, `xlIntlMacrosheet`) and by the `macrosheets/` part path.
8. **Image memory: fixed.** A decoded-bytes budget (pixels times bytes per pixel from the colour model, `APP_FILES_IMAGE_MAX_DECODED_BYTES`, default 128 MiB) is checked before decoding. A 16-bit PNG over budget is a corpus row.
9. **No HTTP upload path: fixed.** `fileshttp.Upload(opts, kind)` is a plain handler. It takes a raw body (name from Content-Disposition) or exactly one multipart file part via MultipartReader, under MaxBytesReader plus the policy cap, and answers 201 with the receipt in the data envelope.

- Nested-archive and in-archive PDF/image limits are documented.
- budgetReader loops until it gets a byte or an error. Done.
- Re-encoded size is capped. Done.
- TTL is capped at seven days, and the signed message is unchanged; the tenant is for P4.
- `%` is mapped to `_` in the fallback filename. Done.
- fileshttp handlers panic at construction when wiring is missing. Done.
- csvx small forms are neutralised. Done.
